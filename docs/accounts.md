# 账号与密码

## 同一台电脑切换成员账号

本地会话、输入草稿、整理任务、传输记录和个人成果按服务器地址、端口、登录账号及服务器指纹区分。同组成员也不会因此共享本机会话；团队成果仍按项目权限共享。切换账号保留各自数据，切回原账号即可继续查看，包括已关闭的会话；断网时使用最近一次验证成功的账号，登录失败不会把旧记录归给新账号。

切换后会重置当前会话选择、预览和弹窗，旧请求的返回不会进入新账号界面。运行中的会话、整理及未完成的传输或保存需先停止或完成，再切换账号；清理上传缓存只处理当前账号的记录。此隔离用于工作台内的账号切换，不改变 Windows 文件权限。

同一台电脑上，在任意窗口登录同一账号都会使用同一份会话、输入草稿、整理记录、个人成果和传输状态。多个窗口共用这个账号的运行实例；关闭其中一个窗口不会停止其他窗口正在使用的会话。不同账号保持隔离，窗口布局各自保存。再次运行 `start-user-dev.cmd` 即可增加窗口，优先恢复尚未打开的已保存账号；全部已打开后进入空白工作台。

账号资料保存在 `%APPDATA%\TeamAgentUser\account-workspaces\身份摘要`。首次使用新版时，会扫描旧的根目录、`instances\数字` 和 `window-state\数字`，按记录的原账号归并，即使旧窗口后来登录了其他人，也能找回原账号的会话。迁移包含消息、输入草稿、整理材料、附件和对应的 Codex 原生历史；同 ID 的旧副本采用最近保存目录中的记录，来源和重复项写入 `migration.json`。完整迁移成功后才启用新目录。

已执行过旧版迁移的账号，登录时会补扫当时遗漏的窗口目录，只添加尚未迁入的记录，已有记录优先。恢复前的文件保存在账号目录的 `migrations\window-recovery-…`；恢复途中中断，下次打开会先完成恢复。已扫描的目录不重复导入，已经迁入后被用户删除的会话也不会重新出现。项目列表按项目 ID 关联会话，不会因旧会话缺少或保留过时的组名而隐藏。

连接中央节点后，若同一账号的本地会话或整理草稿所属项目不再出现在中央项目列表中，原项目会保留在侧栏的“本地历史项目”中。可以查看和继续本机会话、打开已关闭会话、整理草稿及查看个人成果；原项目的共享内容和轨迹上传需恢复原项目访问后才能使用。项目资料修改只保存在本机，不会自动重建远端项目；中央节点再次提供同一项目 ID 后恢复正常同步。不会按名称把旧会话改绑到新项目，也不会因此合并其他账号或服务器的记录。

旧目录保留作为备份，请勿直接删除：原本在其中创建的代码工作目录仍沿用原路径。迁移失败会保留原数据并报告错误。账号同步保存的成果和整理记录不能代替本机会话记录；本次归并只针对同一台电脑。

### 升级后找不到原有会话

先退出用户版的所有窗口，再通过原来的启动脚本打开，使用原服务器地址、端口和账号登录。若旧记录仍在上述目录且身份一致，工作台会自动补齐遗漏记录；Codex 桌面版的原生历史文件不会被改写。

若仍找不到，在发生问题的电脑上进入源码目录运行：

```powershell
node scripts/account-session-diagnostic.mjs --account taowen
```

使用过自定义数据目录时，添加 `--root "实际本地数据目录"`。报告只输出目录、索引文件大小与时间、连接身份、会话数量、关联原生会话的数量及分组匹配情况，不导出正文、密码或令牌，也不会修改资料。它同时检查 `personal` 中登录前导入的本机会话；这些记录属于当前 Windows 用户，不据此归入 taowen 的团队账号。它用于区分旧窗口漏迁移、项目分组变化和登录身份变化。若服务器地址、端口、账号或指纹发生变化，视为不同身份，不自动合并；需核对报告和原目录后再恢复。这个命令不连接中央节点，也不重新导入 Codex 会话。

0.6.2 起，本地管理员免登录：只选择共享目录，重启自动进入。下面的姓名、工号和密码规则用于成员账号；正式 Linux 管理员仍使用服务器账号密码。

创建成员时，“登录账号”可以填写 `张三`、`10086`、`ZhangSan`。登录用户版时填写同一个账号，无需知道服务器的系统用户名。成员姓名只是展示信息，不会自动变成第二个登录账号。

- 账号支持 1–64 个字符：中文等文字、数字、大小写字母、下划线、短横线和间隔号；以文字或数字开头。去除首尾空格，不允许路径符号和 Windows 保留文件名。
- 账号保留输入大小写，登录时应保持一致；不能创建仅大小写不同的重名账号，避免本地 Windows 共享目录重叠。
- 创建、重置和失败恢复时，密码非空即可，不要求 8 位或字符组合；确认密码须一致。保留 4096 字符上限及冒号、换行、空字符限制，以兼容服务器命令输入格式。不会自动修改已有密码。
- 用户组名称与账号规则一致：1–24 个字符，中文等文字、数字、字母、下划线、短横线和间隔号，以文字或数字开头。它是显示给成员看的本地名称，远端 Linux 组名由工具自动生成，不需要管理员迁就 Linux 命名规则。
- 校验失败会显示字段对应的中文提示，不再直接展示 Zod JSON。

## Linux 和旧数据兼容

原本合法的小写账号继续使用原 Linux 用户名和 UID。中文、工号、大写等扩展账号通过固定 SHA-256 映射生成 32 字符的 `wbu_…` 系统用户名；管理员创建、设置密码、分组、停用、恢复、读取状态和用户版 SSH 登录都使用同一映射。账号记录保存原账号和系统用户名；项目角色、上传目录及界面仍使用原账号。

用户组名沿用同一思路，且名称必须整体一致（同一名称的不同 Unicode 写法会先归一化）。原本合法的组名（小写字母开头、14 位以内）系统组名保持 `wb_<团队ID>_<名称>` 不变；中文、大写或更长的名称生成 `wb_<团队ID>_g<SHA-256 前 13 位>`。界面始终显示本地名称，成员看到的工作路径仍为 `/projects/<本地名称>`（支持中文）；因此 Linux 上 `getent group` 显示的是派生名，不含可读名称，排查时请以管理员版界面显示的名称为准。名称之间不能仅大小写不同，与账号重名规则一致。为已有团队改用中文组名后，成员需要升级到新版用户版才能识别。

映射不赋予权限。服务器仍根据已登录的 Linux 身份和用户组检查目录权限，不接管已有同名系统账号。总管理员继续使用服务器已有 root/sudo 账号，原样验证。管理员版遇到扩展成员账号认证失败时只重试一次映射后的账号，角色仍须由受保护的服务器记录确认。

已有账号、组、密码、项目和会话不迁移、不重置；管理员版和用户版应同时升级到 0.6.1，旧版客户端不认识扩展账号。成员在用户版直接填写服务器地址和自己的账号，中文姓名或工号账号均可登录。

正式 Linux 上既有 PAM/SSH 密码策略仍由服务器控制；如果服务器拒绝某个密码，界面会显示实际失败并保留可恢复操作。本版取消的是工作台自身的长度和组合要求。

## 用例验证

- `tests/account-workspaces.test.ts`、`tests/project-session-scope.test.ts`：遗漏旧窗口的补迁移、不同账号隔离、保留新记录和删除结果、恢复中断重试、损坏源文件不影响现有资料、项目分组变化后的可见性。
- `tests/account-session-diagnostic.test.ts`：诊断输出不泄露对话或凭据、不改写资料。
- `tests/local-history-projects.test.ts`：中央项目变化后保留同账号的本地历史入口、原绑定和输入，重启及续聊可用，不重建远端项目，恢复原项目后继续同步，其他账号隔离且共享路径仍需当前权限。
- `scripts/account-session-recovery-smoke.mjs`：真实用户端窗口配合本地 SSH 打桩，验证登录恢复 Codex 导入会话、消息和输入草稿，刷新、重载、重新登录后记录仍在，原桌面历史不变。
- `tests/accounts.test.ts`：规则和中文报错；Windows/Python 映射一致；本地管理员免登录初始化；姓名、工号和混合大小写成员创建、直接登录；真实本地文件上传、轨迹访问限制；重置、停用、移出组、重新连接；通过 SSH/SFTP 协议验证映射后的认证和原账号角色。
- `tests/test_admin.py`：模拟 Linux 用户/组数据库及命令执行，覆盖映射账号创建、密码 stdin、分组、撤销角色、停用、状态回读、UID 变化拒绝和创建中断恢复。该测试不等同于在真实 Linux 发行版上部署。
- `scripts/admin-management-smoke.mjs`：管理员窗口创建姓名、工号和大小写账号，1 位密码；非法账号、空密码和确认不一致的中文反馈。
- `scripts/local-smoke.mjs --accounts`：免登录管理员与两个用户窗口，用 `张三` / `10086` 和 1 位密码完成项目创建、共享文件、轨迹上传、停用与恢复。共享内容写入隔离的真实本地目录。

以上界面脚本可加 `--packaged` 验证实际打包后的 EXE。
