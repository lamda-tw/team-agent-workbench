# 管理端网络出口

管理端网络出口用于这样一种部署：成员电脑能访问团队内网，但部分电脑不能直接访问 Codex、Cursor 或 Claude Code；管理端电脑具备可用外网或已有代理。它是可选通路，不改变团队账号和项目权限；成员可直接连接管理端，也可通过已登录的共享服务器中转。

## 先判断是否需要

成员 A 能正常登录团队项目，也能直接连接所选模型服务，保持默认设置即可。成员 B 能打开团队项目，却因所在网络无法连接模型服务；如果 B 能访问管理员电脑的内网地址，管理员可以开启网络转发并给 B 一段接入码。B 把接入码填入用户版后，工作台启动的模型 CLI 经管理员电脑连接模型服务。B 仍用自己的模型账号和额度，团队项目继续走原来的 SSH/SFTP 连接。

“网络出口”指管理员电脑提供的**模型连接中转**，不需要成员把代码、模型账号或团队 SSH 密码交给管理员。接入码只用于连接中转，不能当作团队账号或模型账号。管理员版需保持运行；成员恢复直连后可关闭该选项。

## 从用户看到的连接过程

1. 管理员在管理员版开启出口，确认它自己能够访问所需的 Codex、Cursor 或 Claude Code 服务，再把接入码交给需要转发的成员。
2. 成员在用户版勾选“通过管理端访问模型服务”，粘贴接入码，仍用自己的 SSH 账号登录团队项目。
3. 成员核对自己的模型 CLI 登录状态，创建会话并发送一次请求。收到模型回复才说明成员端整条连接可用。
4. 若团队项目打不开，检查 SSH、组成员关系和共享权限；若项目能打开而模型不能回复，分别检查成员到管理端、管理端到模型服务和成员的模型账号。

以下是实现层面的连接路径；普通成员按上述界面步骤操作即可。

```text
用户版启动的 Codex/Cursor/Claude Code CLI
    ↓ 仅该 CLI 的 HTTP_PROXY / HTTPS_PROXY
127.0.0.1 随机端口（用户版进程）
    ↓ TLS 加密、证书指纹固定、接入码校验
管理端电脑:18443
    ↓ 本机直连 / HTTP CONNECT / SOCKS5
Codex、Cursor 或 Claude Code 服务
```

模型服务的 TLS 连接穿过隧道，仍由本机 CLI 与厂商建立。管理端不解密提问、回答或个人模型账号凭据，只能看到用户端上报的团队账号标识、产品、目标域名、连接状态和流量。这个账号标识便于排查连接，不作为权限认证；网络出口的访问控制来自接入码。成员继续使用自己的 Codex/Cursor/Claude Code 账号和额度；本功能不提供共享模型账号。

## 查看代理监控与 CLI 异常

管理端 **网络出口 → 运行监控** 每 2 秒更新在线成员与隧道数、上下行速率及累计流量、最近两分钟趋势、连接失败与接入拒绝次数。在线成员列表显示来源地址、目标域名和当前连接流量；“最近连接”默认收起，展开后查看历史记录与失败原因。数字统计的是当前这台管理端承接的流量；多个管理端分别统计自己的出口。

代理运行在独立后台进程中。面板里的 CPU 是该代理进程占整机 CPU 总容量的比例；内存是该进程的驻留内存，不包含管理界面、共享空间操作或本机其他 Codex 会话。关闭出口会释放代理进程，重新应用设置或启动管理端会重新开始累计。最近连接保留 100 条，累计流量不因旧记录被移出而减少；短暂的连接检测和状态上报不计入模型隧道流量。

**用户端 CLI 状态** 单独显示等待服务响应、重连次数、HTTP 401/403/429/5xx 等失败及恢复状态。工作会话和成果整理页面也会立即显示重连或失败提示；真正收到服务输出后才清除异常。403 表示访问被拒绝，不能仅凭它认定是密码错误或网络不通。

模型 HTTP 状态位于加密隧道内部，代理不会解密读取。更新后的用户端会通过已验证的出口连接上报状态类别、错误码和重试次数，每 30 秒补报最新状态；不上传提示词、回复、完整诊断文本或凭据。超过 90 秒没有更新会标记状态过期。旧用户端仍可转发流量，但没有这项 CLI 状态上报；工作台之外启动的 CLI 也不在监控范围内。出口断开期间无法即时上报，用户端仍显示本地异常，恢复后继续补报。

“连接成功”“正在收发”只说明隧道状态；需同时查看 CLI 状态，不能把它当成模型请求成功。更新此功能需两端获取新代码并在现有任务结束后重新启动；不要在成员使用过程中重启出口。

## 管理端配置

网络出口分为 **运行监控、成员接入、出口设置、连接诊断** 四个页签。首次未启用时默认打开设置；已启用时默认打开监控。切换页签保留未保存设置，后台刷新不会因监控数据变化重置输入；设置页签的小圆点提示有未保存修改，可保存应用或放弃修改。

1. 打开管理员版左侧 **网络出口 → 出口设置**。此页不依赖共享空间是否已经登录。
2. 开启 **启用管理端出口**。程序首次启动时已经自动生成自签名 TLS 证书、证书指纹和随机接入码，不需要手工运行证书命令。
3. 核对“提供给成员的地址”。默认使用管理端电脑名；成员电脑无法解析时改成管理端固定内网 IP。
4. 监听端口默认 `18443`。监听地址默认 `0.0.0.0`，允许内网网卡接入；需要限制网卡时在折叠区修改。
5. 选择管理端访问外网的方式：
   - **本机直接访问**：管理端本身可以访问模型服务。
   - **HTTP 代理**：填写上游代理地址、端口及可选账号密码。
   - **SOCKS5 代理**：填写上游代理地址、端口及可选账号密码。
6. 在 **成员可通过出口访问** 中勾选允许转发的服务。这是成员访问权限，不要求管理端电脑安装、启动或登录对应 CLI。点击 **保存并应用** 后生效；下次打开管理员版会自动恢复。
7. 切换到 **连接诊断**，分别测试 Codex、Cursor、Claude Code。三个测试不受成员转发权限或出口启停影响，使用已保存的上游设置；未保存修改会在界面提示。测试只检查管理端到目标服务地址的网络连接，不验证成员模型账号或配额，也不会开放转发权限、重启出口或计入成员模型流量。

出口关闭时，测试使用临时后台进程，不打开成员监听端口，测试结束或失败后释放；出口运行中直接复用现有进程，保留连接与监控记录。确认网络和成员访问范围后，再复制用户端接入码。

在 **成员接入** 选择“直连管理端”或“经共享服务器”，只显示所选路线的操作。管理员需要提供的信息只有一段接入码。它已经包含管理端地址、端口、TLS 证书指纹和随机访问密钥，不需要再让成员分别填写这些字段。接入码等同于本出口的访问凭据，只发给需要转发的成员。证书指纹和“更新接入码”位于折叠的 **接入凭据与安全** 中；更新会让两种路线的旧接入码立即失效，所有使用者需要重新粘贴。

启用出口后，关闭管理员端窗口会转入系统托盘，继续保留出口和本次登录的反向隧道；双击托盘图标或再次运行入口可重新打开。选择托盘菜单“退出并停止转发”、注销或关机会停止；系统托盘不可用时，界面会明确提示关闭窗口将停止转发。普通驻留模式不要求本机管理员权限。防火墙规则仍需运维配置，只对公司内网来源开放所选 TCP 端口，不应暴露到公网。

上游代理密码、出口访问密钥和用户端保存的接入密钥在 Windows 支持时使用 Electron `safeStorage` 加密后写入各自应用数据目录。普通配置文件不包含这些明文。TLS 证书和私钥只保存在管理端本机数据目录。

## 经共享服务器中转

成员能连接共享服务器，却无法直接连接管理端电脑时，使用此选项。

```text
用户端 → 共享服务器的 SSH 端口（如 2202）→ 服务器内部中转端口
                                                  ↓ 管理端主动建立的 SSH 反向隧道
                                             管理端出口 → 模型服务
```

1. 更新管理端与用户端。管理端用已有的 Linux root / sudo 账号登录共享服务器，进入 **网络出口 → 成员接入 → 经共享服务器**。
2. 确认出口已保存并运行，点击 **启用反向隧道**。程序使用本次已验证的 SSH 登录信息，分配仅限服务器内部访问的端口，并允许团队成员连接该端口；其他管理员的出口会保留。
3. 点击 **检测完整隧道**，验证本机 → 共享服务器 → 本机出口的连接、证书指纹和接入码，再 **复制中转接入码**。直连管理端使用的普通接入码在另一条接入路线中。
4. 首次使用的成员应断开共享连接后重新登录，勾选 **通过管理端访问模型服务** 并粘贴中转接入码，界面会自动选中 **经共享服务器中转**。已在使用的会话也可在网络与登录设置中切换；运行中的任务需先结束。
5. 在用户端重新检测连接与模型登录，再发送一次请求。当前共享服务器必须与接入码中的地址、SSH 端口和已验证身份一致。断开或不允许转发时会显示原因，不会自动改成直连。

共享服务器已有 SSH `2202` 即可作为外部入口，内部端口仅监听 `127.0.0.1`，不需要额外申请对外端口。成员电脑和管理端电脑均需能主动连接这个 SSH 入口；共享服务器不必直接连接管理端的 IP 或 `18443`。实际网络验证中，共享服务器连接管理端的 `80、443、2202、18443` 都超时，而生产代码使用反向隧道完成了 TLS 握手及证书校验。

SSH 密码仅在管理端本次运行的内存中保留，用于隧道重连，不写入配置文件。短暂断网按递增间隔重试，最长间隔 30 秒，保持原内部端口和接入码；账号认证失败或服务器身份变化会停止自动重试，需重新登录。关闭管理端窗口会保留后台转发；主动断开管理连接或选择托盘菜单“退出并停止转发”，才会关闭隧道并清除内存中的登录信息。再次启动并登录原服务器后自动恢复已启用的隧道。关闭网络出口会暂停隧道，重新开启后恢复。

后台驻留的启动、恢复窗口和退出步骤见[后台转发说明](background-egress.md)，统一使用管理端入口。

多个管理端分别分配内部端口，停用某一台只关闭它自己的隧道。端口占用时显示连接失败并重试，不会自动换端口使已分发的接入码失效。**停用中转** 保留成员允许地址，便于下次恢复；如需彻底撤销地址，使用下方“管理允许的出口”。隧道连接数、重连次数和内部端口在本页单独显示；反向 SSH 转发在管理端主进程中运行，不计入“代理监控”中独立代理进程的 CPU/内存。

服务器能够直接连接管理端 IP 时，仍可展开 **高级：服务器直接连接本机**，使用 **测试服务器到出口** 和 **允许此出口中转**，再切换到“直连管理端”复制普通接入码，成员另行勾选“经共享服务器中转”。这项 TCP 测试不代表模型账号可用；若此直接模式受出站端口限制，可调整管理端出口端口或优先使用反向隧道。

只有服务器 root / sudo 管理员可以修改中转规则；项目组管理员和普通成员只能选择已允许的路线。服务器保留 SFTP 专用登录、目录隔离和无终端权限，通过 OpenSSH 的 `AllowTcpForwarding local` 与精确 `PermitOpen` 地址列表限制转发，代理、X11、Unix socket 和网络设备转发仍关闭。配置经过 `sshd -t` 检查后重载，失败恢复原配置。反向隧道会在每次连接后核对 Linux 实际监听地址；若 SSH `GatewayPorts` 将监听扩大到非回环地址，程序会关闭该隧道。指令含义见 [OpenSSH 官方说明](https://man.openbsd.org/sshd_config#PermitOpen)。

新增权限在新的 SSH 连接生效；已经登录的成员应先断开再登录。**管理允许的出口 → 移除并断开成员连接** 会关闭全体成员现有的 SSH 连接，包括共享文件传输和模型中转，防止旧连接继续保留已撤销权限；管理端出口本身继续运行。再次登录后按新的地址列表限制转发。

中转只搬运加密流量，用户端仍验证管理端证书指纹和接入码。反向隧道下管理端监控的来源 IP 为本机回环地址，直接中转时为共享服务器地址；成员账号标识、CLI 状态与流量统计保持可见。本地文件夹模拟共享区不支持中转。中转接入码使用 `TAE2` 格式，旧用户端会拒绝该格式，需要更新；原 `TAE1` 直连接入码仍兼容。

## 用户端配置

1. 本机能直接访问模型服务时保持选项关闭，按原方式登录团队共享空间。
2. 本机不能直连时，在用户版登录窗口勾选 **通过管理端访问模型服务**。
3. 首次粘贴管理员提供的接入码；之后工作台会记住接入信息和密钥，除非管理员更新接入码。
4. 无法直接连接管理端时勾选 **经共享服务器中转**；管理员须先按上节允许该出口。
5. 继续填写团队 SSH 账号密码并登录。出口选项只在认证成功后应用到该账号，登录失败不会改动之前账号的网络设置。中转需保持共享服务器在线，出口异常不会改变项目权限。

启用后，用户版自动在 `127.0.0.1` 上选择空闲端口，并向工作台启动的 Codex/Cursor/Claude Code 进程注入 `HTTP_PROXY`、`HTTPS_PROXY`、小写兼容变量、`NO_PROXY` 和 `NODE_USE_ENV_PROXY`。关闭选项会停止本机代理且不注入这些变量。系统代理、浏览器和工作台之外启动的 CLI 不会被修改。

出口设置改变时，工作台会关闭空闲的 CLI 运行时并重新检测账号。正在运行或等待授权的会话不会在中途切换网络，需等待任务结束后再修改。

## 固定边界

- 管理端只接受接入码正确且证书指纹匹配的 TLS 连接。
- 目标仅允许配置中启用的 Codex/Cursor/Claude Code 官方域名后缀和 TCP 443；任意域名、任意端口及普通 HTTP 请求会被拒绝。
- 用户端不会信任系统中任意证书；它固定校验接入码携带的管理端证书 SHA-256 指纹。
- 管理端不记录报文正文。界面中的最近连接记录只保留当前进程内的目标域名、状态和字节数。
- 接入码用于控制网络出口，不替代 SSH 成员身份，也不授予任何共享空间权限。

若厂商今后新增必需域名，旧版白名单可能导致该请求被拒绝。先确认域名属于官方服务，再由开发者更新 `src/core/egress.ts` 的产品白名单并重新发布客户端；不要把出口改成任意目标的通用代理。
