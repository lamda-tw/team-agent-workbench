# 多台管理端的成员同步

同一团队的管理端连接同一个中央节点及团队根目录。账号登记与权限在中央节点生效，管理端保留可离线查看的缓存。分别初始化的节点属于不同团队，不按姓名或账号自动合并。

## 使用方式

- 首次连接获取成员与项目组全量；之后每 10 秒获取变化。重新连接、窗口重新获得焦点和本机管理操作结束时立即检查。
- 其他电脑新增、修改成员后，本机列表自动更新。已打开的表单保留输入；目标成员变化时展示打开时和现在的状态，需要明确确认后才能继续。
- 组与角色的修改提交具体加入、移出、角色变更。确认最新状态时保留本次调整，也保留其他电脑对未调整项目组的修改。
- 密码、账号启停、接任成员均校验成员版本。不同成员的操作互不阻塞为冲突；同一成员的过期操作会被拒绝。权限冲突由管理员确认，AI 不自动授权。
- 已同步过的团队可离线创建成员，显示“待开通”；恢复中央节点连接后自动提交，客户端重启后仍保留。首次使用需要先连接并初始化团队。管理登录密码不保存在队列中，重启后 SSH 管理端仍需要登录。
- 同名账号（包括仅大小写不同）会阻止开通，其他待开通成员继续处理。可以移除待办并使用正确账号重新创建。移除待办不删除服务器已经创建的账号。
- 部分开通失败仍使用“待恢复操作”核对并继续。完成恢复后，相关待办根据服务器回执自动消失。

## 实现约束

- `members_sync` 返回团队 ID、变更序号、成员/组增量、删除标记和所查询请求的完成状态。缓存和待办按管理窗口的节点目录保存到 `members.json`，由单个串行队列写入。
- 成员版本包含账号身份、状态、所属组、角色及访问版本。修改密码、启停和组分配都会更新访问版本。服务端在团队锁内校验版本，再执行操作。
- `members_apply` 要求团队 ID 和唯一请求 ID；成功回执与最终状态一起保存。重试相同请求返回已完成结果；改变请求内容须使用新 ID。部分失败不自动重复执行系统开通步骤。
- 客户端缓存不保存凭据或服务端回执内部信息。服务器回执仅为密码请求保留加盐校验值，以拒绝同一请求 ID 被用于不同密码。
- 同一个地址/目录的团队身份发生变化时，停止同步、开通和管理写入。未完成任务不会自动转移到新团队。
- 管理程序随每次 SSH 请求发送，无需为成员同步另起管理端服务；读增量不修改操作系统权限，也不重启成员连接。成员操作使用原有权限配置流程。
- 多台管理端都应更新到包含此协议的版本。旧版本的全量组分配入口仍不具备版本检查，不应继续用于并行成员管理。
- 已部署节点还应通过“更新服务端功能”更新文件服务，使成员自行修改密码也更新访问版本，阻止过期的管理员密码表单覆盖这次修改。
- 本地共享目录模式用于模拟权限测试，保留文件锁与同样的同步、冲突检查；它不提供操作系统级账号隔离。
