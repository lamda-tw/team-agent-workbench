# 会话相关动态提醒

当前项目的每个未归档工作会话都参与新增动态匹配。同账号多个窗口共用主进程调度器；每个窗口选中的项目都可参与。归档会话、其他账号的会话和后台整理会话不参与。

## 使用方式

进入项目后自动建立动态基线，已有动态不回扫。主进程每 15 秒检查团队动态，窗口最小化后继续运行。新成果、新修订及合并产生的成果进入队列；本人产生的动态不参与推荐。每条动态在每个会话内分别记录处理状态。

本轮运行期间不展开提醒。本轮结束后，输入框上方显示一个聚合入口，例如“新增 2 条可能相关的动态，另有 6 条待处理”。下次发送时，如果有尚未展示的新推荐，会先展开选择面板，输入内容保留。后台尚未完成时发送不等待。

面板按动态时间倒序排列，默认展示 3 条，可展开其余条目。每条只显示一句关联理由和一段可核对的原文，不显示评分、等级或建议操作。可以查看全文，由成员判断是否采用。

- **加入当前会话**：冻结所选成果的版本，将引用选入下一条消息；不自动存入个人成果库。
- **存入个人成果库**：保存个人副本，不自动加入会话。
- 两项可以同时勾选，也可以逐条选择。批量勾选只影响当前展开的条目。
- **本会话忽略**只影响这一会话和这一动态版本。
- **本轮跳过，直接发送**保留候选，之后可从入口查看；不会每轮重复展开。新动态到达后再次提示。
- 已在个人库中的成果会显示“已存入”，仍可在其他会话中选择加入。会话间的忽略和采用互不替代。

执行前重新核对成果版本和访问权限。版本变化不会静默替换为最新版。部分操作失败时显示错误并保留成功结果，重试不会重复创建引用或个人副本。

## 摘要与后台执行

摘要更新现在同时生成一句工作日志，由专用线程串行保存；每个 Session 保留最近 5 条，作为同项目会话间的自动增量参考。详见 [项目会话日志](project-journal.md)。团队新增动态匹配仍只读取摘要，不读取完整对话。

每个会话有自己的 `.workbench/sessions/<sessionId>/handoff.md`。工作台在一轮结束后使用旧摘要和新增对话更新同一文件，目标约 800～1500 字。主会话不再直接写摘要；手动更正和自动更新统一经过串行写入、版本检查和原子替换。旧编辑不能覆盖新摘要。

匹配任务只读取该会话的阶段摘要和新增动态，不发送完整对话或展开全部附件。只有新动态会创建判断任务；运行中的会话或尚未完成摘要的会话先保留任务，条件就绪后继续。已经判断为相关或不相关的动态不会因为摘要变化、完成下一轮对话、切换会话或普通刷新而重新判断；已生成的推荐保留，采用前仍核对版本和权限。

两类失败分别提示，均无手动重试入口：动态区域仅提示当前会话尚未完成的新动态判断；单独的摘要或日志更新失败不会让动态区域出现。摘要和日志的更新问题放在“AI 参考内容”内，仅展示状态、原因和自动恢复条件。

| 待完成工作 | 自动继续的触发 |
| --- | --- |
| 摘要或一句话日志生成失败 | 本会话下一轮结束、摘要被更正、对应 CLI 登录/服务恢复；重新打开会话或重新进入项目时恢复待办。新动态需要该会话摘要时也会尝试补齐。 |
| 新动态判断失败 | 同项目有真正的新动态入队，或相关连接/CLI 恢复后，续办尚未成功的判断。 |
| 新动态原文缺失 | 收到该成果同版本的文件恢复事件后，只续办对应任务，不把恢复事件当作新的成果推荐。 |
| 主会话正在运行或摘要版本发生竞争 | 等本轮结束、摘要就绪后消费原有队列，不创建历史动态的重判任务。 |
| 摘要与日志已提交，但本地摘要文件尚未写好 | 由日志线程从已提交记录恢复文件，不重复调用模型或生成日志。 |

定时器只负责消费已入队且满足条件的工作，不再因为失败重试时间到期而重复调用模型。重复扫描到同一动态、重复设置同一活动项目，不会触发失败任务重跑。重新进入项目或启动应用只恢复已有未完成任务，不回扫历史动态。

后台使用会话所选的 CLI、模型和网络路线，消耗对应个人模型账号的额度。每账号同时运行一个后台任务；模型和网络路线一致时，一批可携带至多 4 份会话摘要和 20 个动态，动态文字总预算为 24000 字符，单条最多 8000 字符。长文的匹配可能不覆盖截取范围之外的内容，原团队动态仍可手动浏览。摘要增量输入有长度预算，不包含工具日志全文。

Codex 使用独立原生上下文、只读权限并禁用命令工具及已配置 MCP；Cursor 要求 CLI 提供 Ask 模式；Claude 使用无工具、无 MCP 的临时会话。匹配结果的原文片段须确实出现在输入中，否则按失败重试。后台任务不会修改项目文件、发布成果或直接向工作会话发送消息。

队列与处理记录保存在账号本机数据目录的 `activity-assistant.json`，应用退出后停止执行，重新打开并进入项目后继续处理待办。账号私有空间同步不上传这些推荐记录。普通新成果动态保留在团队动态页，主动提醒由会话相关入口承接；删除、文件缺失等提醒继续保留。

## 验证范围

后台测试覆盖多会话匹配、首次基线、增量去重、账号和项目隔离、归档、主轮次与摘要更新竞争、原文核对、失败重试、重启恢复、独立操作和版本变更。另有 CLI 协议替身和 React 服务端渲染测试。真实模型判断质量、桌面布局及各厂商实际 CLI 兼容性仍需在部署环境验收。

2026-10-12 验证：类型检查与隔离构建通过。全量后台回归执行 420 项，首轮 417 项通过，3 个用例仍依赖旧的“加入会话自动存库”行为；改为显式存库后，相关 20 项复测通过。最终相关回归 71 项通过，随后新增单条原文缺失隔离检查，最新功能测试 16 项通过。测试使用临时目录、协议替身和服务端渲染，未调用真实模型或启动桌面窗口。
