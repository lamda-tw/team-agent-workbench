# 项目会话日志

每个账号在每个项目中有一份会话日志总览。所有未关闭的工作 Session 默认参与，包括 Codex、Cursor、Claude 和子会话，不需要开启 Beta 功能。输入框下方的“项目会话日志”可查看和刷新总览。

## 生成与保留

每轮对话结束后，后台用旧阶段摘要和本轮新增对话，一次生成新版摘要及一句日志。日志目标 30～60 字，硬上限 80 字，只记录实际工作、结论或阻塞；未验证、失败和计划不能描述为已完成。生成中引导属于同一轮，不另外计数。工具事件不独立产生日志。

每个 Session 按用户轮次 ID 去重，只保留最近 5 条；旧日志淘汰不影响独立摘要中的有效结论。模型调用异步进行，不等待日志就能继续发送；尚未生成的内容会在之后发送时补上。生成失败保留旧摘要、日志和未完成轮次，在下一轮结束、对应 CLI 恢复、摘要更正或会话/项目恢复时自动续办，不提供手动重试按钮，也不按固定间隔反复调用模型。新动态判断需要该会话摘要时也会尝试补齐。补齐时按原轮次顺序处理，已成功写入的日志不重复生成。

完成事件进入摘要任务队列，一个后台模型任务串行消费；日志持久化由一个专用 Node Worker 线程按队列写入。摘要和五条日志先作为同一份 JSON 原子提交到本机账号数据目录的 `project-journals/<sessionId>.json`，再更新 `handoff.md`。若应用在两个步骤之间退出，下次读取会修复未完成的投影。人工更正也走同一写入通道，迟到的后台结果不能覆盖更新后的版本。

## 发送与读取

首次向一个原生 CLI 上下文发送消息时，附带当前项目各会话日志及其摘要副本路径。之后只发送新增条目、摘要版本或名称变化、旧条目淘汰和会话移除；没有变化时不重复发送。发送失败不推进已提供状态，恢复同一原生上下文保留状态，原生上下文 ID 改变时重新全量提供。

工作台将同账号、同项目的摘要复制到接收会话的工作目录中：

```text
<接收会话 cwd>/.workbench/sessions/<接收会话 ID>/project-journal/
  index.md                    当前完整项目日志
  <来源会话 ID>.md             来源摘要的只读副本
```

发送给模型的是这些绝对路径，不是另一工作目录的原文件路径。Codex、Cursor 和使用独立工作目录的子会话均采用同一规则，不额外扩大原生 CLI 的文件权限。目录和文件不接受符号链接、Windows junction 等重定向，副本按只读属性保存，下次发送时核对并修复被改动的副本。副本只供参考，模型按需读取，不允许写入副本或其他会话目录；具有完整文件权限的程序仍可能主动更改文件属性，这不是额外的操作系统安全沙箱。

总览按 Session 分组，每组附名称、提供方和摘要更新时间。它是某次发送时的快照，不承诺其他会话运行过程中实时同步。日志和摘要是参考资料，不具有指令权限。

## 关闭、删除与隐私

关闭的会话退出后续项目总览；重新打开后可恢复其最近记录。关闭会话后可以点击“删除会话”，清除该 Session、其持久化项目日志及其他会话中的自动摘要副本。后续发送携带移除标记；后台迟到结果、重启恢复均不能使已删除会话重新出现。项目文件、已保存成果及其他会话已经发送给模型的历史记录不被删除。旧内容已经进入原生 CLI 上下文后无法通过删除本地日志撤回。

项目日志不进行账号云同步，不自动作为成果整理的用户输入证据。沿用已有个人跨会话参考规则：向会话提供其他个人会话日志时，关闭该接收会话的轨迹自动上传并提示用户；核对后仍可手动上传实际轨迹。

原“引用会话摘要”Beta 功能保留为手动选取固定快照的补充入口。团队新增动态的相关性提醒仍按独立流程工作。
