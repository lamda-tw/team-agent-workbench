# 管理端：中央节点、用户与组

多台电脑管理同一团队时，成员列表自动同步，过期的权限修改会要求重新确认；离线创建保留为待开通成员。详见 [多台管理端的成员同步](admin-member-sync.md)。

## 同时管理多个中央节点

每个中央节点使用独立窗口。在管理端右上角点击 **连接其他中央节点**，或再次双击原来的 `start-admin-dev.cmd`，即可打开另一个管理窗口。重复启动时优先恢复尚未打开的已保存节点；都已打开时显示新的连接窗口。不同节点分别输入 SSH 管理账号和密码，窗口标题与右上角显示当前目标。密码仍只保存在本次运行的内存中。

在已有窗口的连接设置中填写其他节点，会在独立窗口连接，原窗口继续工作。目标节点已经打开时，直接唤起它；同一地址、SSH 端口、管理账号和团队根路径视为同一个管理目标。本地模拟模式按共享目录区分。

用户管理、项目组、空间统计、服务器修复与反向隧道均只操作当前窗口对应的中央节点。每个窗口拥有独立的网络出口设置、证书、接入码和监控。新窗口自动分配不同的本机转发端口；已保存的端口保持不变，以免原接入码失效。端口被其他程序占用时需在该窗口的出口设置中处理，不会自动替换已分发的地址。

成员使用哪一个窗口生成的接入码，就连接哪一个出口。关闭已启用转发的窗口会保留其托盘后台；托盘提示包含节点和端口。选择 **关闭此节点并停止其转发** 只停止该节点，其他窗口继续工作。普通 SSH 管理连接断开时，该窗口的反向隧道停止；直连管理端的本机出口可独立运行。

升级保留原管理端的数据目录和接入码。新增节点的数据存放在同一管理端数据目录下的 `nodes/<编号>/`，分别保存连接资料、证书和出口凭据。测试使用临时目录，不修改真实服务器。

## 用户与组管理

管理员在 Windows 管理员版打开共享区后进入“用户管理”。0.6.2 起，本地模拟模式首次只选择共享目录，后续启动自动打开，不要求管理员账号密码；Linux 模式仍验证服务器账号密码。本地模拟模式和 Linux SSH 模式共用界面，实际权限分别由权限桩和服务器系统账号落实。

总管理员还可从左侧进入“共享空间”，查看全局容量、项目组、用户和文件夹占用。该页面只做只读统计，具体口径和验证见 [共享空间管理说明](shared-storage-admin.md)。

最新开发版将“创建用户”和“创建用户组”并排放在页面右上角，两种视图下位置一致；组内保留“组内创建用户”和“添加已有用户”。该交互已包含在 0.6.2 管理员版安装包中；开发时仍可双击仓库根目录 `start-admin-dev.cmd`。

创建用户组时填写的是**用户组名称**：界面和成员看到的都是它，支持中文、字母、数字、下划线、短横线和间隔号，最多 24 个字符，例如 `ocr` 或 `实体抽取`。远端 Linux 系统组名由工具自动生成（原本合法的小写名称保持 `wb_<团队ID>_<名称>`，其余使用 `wb_<团队ID>_g<SHA-256 前 13 位>`），工作目录为 `/projects/<用户组名称>`。名称不能与已有组仅大小写不同。创建中文名称后，成员需要使用新版用户版。

开发和本地打桩均使用仓库根目录的 `start-admin-dev.cmd` 与 `start-user-dev.cmd`。不再生成按成员命名的独立启动脚本。管理员交互验证运行 `npm run test:admin-ui`，多账号和多工作组验证运行 `npm run test:workgroups-ui`；测试使用各自的临时数据目录和本地共享区。已有演练数据保留，旧的个人数据目录可通过 `WORKBENCH_DATA_DIR`、管理员数据目录通过 `WORKBENCH_ADMIN_DATA_DIR` 传给统一入口。

## 入口与行为

| 操作 | 入口 | 结果 |
| --- | --- | --- |
| 查看全部用户 | 全部用户 | 每人一行，显示状态、所属组及各组组管理员身份 |
| 查看组的成员 | 按组查看 → 点击组名 | 展开成员，显示本组角色；同一人可出现于多个组 |
| 独立创建用户 | 页面右上角创建用户 | 所属组默认空，可选择任意已就绪的组 |
| 创建用户组 | 页面右上角，与创建用户并排 | 新建组并准备对应工作路径 |
| 在组内创建 | 按组查看 → 组内创建用户 | 默认加入当前组，可调整所选组及组管理员身份 |
| 用户加入已有组 | 全部用户 → 加入用户组 | 选择尚未加入的组，设置普通成员或组管理员 |
| 将已有用户加到组 | 按组查看 → 添加已有用户 | 按姓名或账号搜索，可多选并统一设置本组角色；搜索不清空已选项 |
| 查看 / 修改用户所属组 | 点击用户姓名，或组与组管理员 | 勾选或取消组；对已选组单独授予组管理员 |
| 修改单组身份 | 点击用户的组标签，或组内设为 / 取消组管理员 | 只更新指定组的角色 |
| 从用户一侧移出组 | 点击用户组标签 → 成员身份选择移出此组 | 解除本组成员关系和组管理员权限 |
| 从组一侧移出成员 | 按组查看 → 移出本组 | 与从用户一侧移出效果相同 |

“全部用户”和“按组查看”同时提供搜索、角色和状态筛选。未分组用户在全局可筛选，在层级视图中有单独区域。无匹配结果、空组、无可添加用户会明确提示。取消对话框不提交变更；重复账号会在对话框显示错误。操作成功后的绿色提示会在数秒后自动消失，红色错误提示保留到手动关闭。

## 权限与数据含义

组管理员是一个**组内角色**，可在对应工作路径下创建项目，不是总管理员。用户可以在 NLP 组担任组管理员，同时是 OCR 组的普通成员。

移出组会撤销对应访问资格和本组组管理员角色，保留账号及其他组角色。已上传成果和轨迹仍留在项目目录中。要禁止整个账号登录，使用“停用”；此版不提供永久删除账号、组或目录的操作。

独立创建且未分组的用户可以用服务器地址和个人账号登录，但不会出现工作台或新建会话入口；用户端显示“还没有加入工作组”。管理员为其分组后，刷新即可发现对应共享空间，无需用户填写路径或取得新的配置文件。一个账号加入多个组时，用户端按组分开显示。Linux 成员权限变更会断开旧连接，需重新登录；本地打桩刷新即可。

单组操作的请求只包含账号、目标组和期望身份。后端在团队锁内读取最新成员关系再更新目标组，避免管理员甲在 NLP 组操作时覆盖管理员乙新增的 OCR 身份。Linux 使用固定 Python 程序及系统命令，并沿用操作记录和失败恢复；恢复时也保留其他组的当前状态。

## 可重复验证

```powershell
npm run check
python -m unittest discover -s tests -p test_admin.py
node scripts/admin-management-smoke.mjs
node scripts/admin-management-smoke.mjs --packaged
node scripts/local-smoke.mjs --packaged
node scripts/smoke.mjs --packaged
```

用户管理界面用例使用独立的临时共享目录和模拟账户，不修改演练中的 Alice、Bob。结果及截图保存在 `.test-data/admin-management-*/`。用例覆盖两个视图、两种创建入口、双向加入和移出、组管理员授予与撤销、跨组权限保留、未分组用户、搜索筛选、重复账号、取消操作及重启保存。

底层还覆盖在线成员撤权、文件保留、两个管理员使用不同新旧快照、无效用户/组/角色及 Linux 部分执行后的恢复。Linux 系统命令测试采用替身，部署公司服务器前仍需实际环境验证。

账号现在支持中文姓名、数字工号和大小写字母，密码非空即可。正式模式的账号映射、旧账号兼容及测试范围见 [账号使用说明](accounts.md)。
