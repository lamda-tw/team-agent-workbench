# AI 参考内容只增量提供

项目内各 Session 的简短工作日志默认自动提供：首次全量，随后只发送变化、淘汰和移除标记。每个 Session 保留最近 5 轮，详情从接收会话目录内的摘要只读副本按需读取。查看入口为输入框下方“项目会话日志”。生成、线程队列、关闭/删除和目录约束见 [项目会话日志](project-journal.md)。

同一原生会话首次使用项目说明或参考文件时，工作台向 CLI 提供快照路径、来源和哈希。后续对话沿用该会话上下文，不再逐轮拼接同一段资料。采用新版项目说明或添加新资料后，仅补充新增版本一次。各个会话独立记录，不跨会话复用已发送状态。

每条用户消息分别保存原始输入 userText 和实际发送内容 text。聊天气泡只显示原始输入。项目说明在下一次发送时自动换成最新快照，不提供单独的更新操作；阶段摘要仍在会话工具栏的“AI 参考内容”中查看。轨迹 JSON、Markdown 和工具事件保留实际输入，不删除审计信息。

用户气泡不展示自动附加的摘要约定、参考文件信息和项目会话日志。原生历史刷新时保留用户原文、引用接收状态和引导标记；同样的输入重复发送时按消息分别匹配。旧记录缺少用户原文时，显示和加载共用恢复逻辑：只识别已知摘要/快照，以及具有完整固定说明、本会话日志路径和日志结构的附加段；用户已保存的原文、普通引用及模型回复照常显示。首次全量和后续增量日志都遵循此规则。

是否已经提供资料，以 CLI 接受的消息为准。Codex turn/start 返回成功后标记；Cursor session/prompt 正常返回后标记。如果发送前失败，下次重试仍携带资料。恢复原生会话、重启客户端、切换模型或修改权限后，已接受的引用状态保留；原生会话 ID 改变则重新提供上下文。仅检查本次新增引用的快照完整性。

个人或团队成果加入会话后，会先出现在输入框上方的待发送资料中。发送前可点击成果旁的“撤销加入”，删除此会话的快照和待发送选择；个人成果库与共享区原件不受影响。已经被任一原生对话接受的快照不能撤销，即使当前原生会话需要重新补充该资料；历史对话保持原样。

删除个人成果后，尚未发送的对应引用退出可选列表，旧勾选也不会再带入普通消息、生成中引导或新建整理任务。团队引用在成功读取当前和历史成果清单后核对；原件确已不存在才退出待发送列表，断网、权限失败或历史查询不完整时不推断删除。归档仍算保留，团队原件删除不影响独立的个人副本，已进入对话的历史与原始快照保留。缺少成果 ID 的旧版引用按来源路径识别，补齐关联信息，并支持“撤销加入”；不按标题相似合并或关联成果。项目说明、任务资料和父会话继承内容不在此清理范围内。

升级时识别旧消息末尾由工作台生成的完整资料段，以及新旧阶段摘要约定：只识别本会话已有快照的精确路径、来源、哈希，不删除用户普通文字或对标记的引用。旧消息原文仍保存在 text 中；生成 userText 用于展示。旧会话已有后续模型或工具响应的资料视为已提供，无响应的旧输入保守地在重试时补充。
