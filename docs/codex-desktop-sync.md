# Codex 桌面同步

桌面联动已接入普通用户端的会话工作流。打开用户端、查看团队资料、新建空会话均不需要同时打开 Codex。联动会话在首次发送时启动或复用共享后台；发送或恢复同步时，如果 Codex 未运行，会自动打开对应会话。此前本机真实桌面联调的消息与上下文结果保留在本文后半部分。

## 在现有工作台中使用

“接入 Codex 会话”的列表直接读取当前 Windows 用户的本机 Codex 记录，不要求先启动 Codex。支持普通 `.jsonl` 和 `.jsonl.zst` 压缩历史；列表只展示未归档会话，已导入的会话会标记为“已在工作台”。列表打开后新增的会话可点击“刷新”读取。首次接入共享后台时的退出提示只影响后续联动，不影响读取导入列表。

1. 从原来的 `start-user-dev.cmd` 或用户版程序打开工作台，按原来的方式使用成员账号连接中央节点。
2. 桌面同步是普通功能，无需打开 Beta。每条新会话可独立选择是否同步。
3. 点击 **新建会话**，选择 **Codex**，默认打开 **与 Codex 桌面版同步**，也可关闭。使用管理端网络出口时此项不可选，并显示原因；普通会话仍可创建。已有普通会话在本轮结束后可通过 **… → 同步到 Codex** 接入。
4. 在工作台直接发送任务。程序按需启动一个受连接验证保护的本机 Codex 后台，同一 Windows 用户、同一 Codex 个人目录中的其他联动会话复用该后台，各自创建独立的原生会话 ID、工作目录、模型和执行权限。Codex 未运行时自动打开当前会话；已经联动运行时，后续发送继续复用，不反复切换原生窗口。
5. 需要原生界面时，点击会话工具栏 **… → 在 Codex 中打开**。原生程序连接同一后台，直接进入对应会话。首次发送前点击此按钮，也会准备空原生会话；后台未登录时可从原生界面完成个人登录。
6. 任一端发送后，同一会话等待本轮结束再从另一端继续。不同会话可以并行运行；关闭一条工作台会话不关闭其他会话或共享后台。
7. 授权和提问在发起任务的窗口处理；另一端仅提示 **请到发起任务的窗口确认**。重新接入生成中的会话会补齐先前消息，补齐期间显示 **正在补齐对话…**。
8. 工具栏显示 **同步中／同步已断开／尚未同步**。断开或重新进入工作台后，可点击 **… → 恢复同步**，补齐历史并恢复原会话订阅；它不会自动重发任务。恢复后先核对已有回复，再决定继续发送。

任务列表中的 **开始任务** 使用同样的新建界面。本机网络下，导入 Codex 原生会话会沿用共享后台。已有普通会话通过 **… → 同步到 Codex** 接入；已同步会话在同一菜单内显示 **在 Codex 中打开**。外侧保留 **提问** 和 **整理成果**。

**接入 Codex 会话** 同时展示桌面版的本地项目和远程项目。本机会话支持跨项目勾选和批量导入；已导入或已关闭的工作台会话不能重复导入。列表同时识别 `.jsonl` 和新版分页历史的 `.jsonl.zst` 完整记录，过滤 Guardian 审查及其他后台子会话。工作目录或历史缺失时保留条目并显示不可导入的原因。

远程项目读取 Codex 桌面版保存的 `remote-projects`，沿用其已有 SSH 主机配置查询远端会话索引，按明确项目归属和远端工作目录分组，并显示主机名称。同一主机上的多个项目共用一次查询；主机无法连接时仍保留项目并显示原因，可点击“刷新”重试。未配置 SSH 的云端连接也会保留项目并提示当前无法读取。

健康的远程会话可勾选并批量导入，按“主机 ID + 原生会话 ID”防重复；关闭后的条目也不可重复导入，同 ID 的不同主机会话分别处理。导入先核对所选主机、会话和历史，再保存工作台关联。远程历史和执行目录保留在原主机，通过 SSH 上的原生 WebSocket 代理连接已有 Codex 后台；不创建替代会话，也不在本机启动 CLI 续接 Linux 目录。首次连接需能在 Codex 桌面版连通该远程项目；工作台菜单提供“连接远程会话”。原生会话忙时不重复发起任务，断开工作台连接不停止远端任务。回归见 `tests/codex-remote-import.test.ts`。

工作台摘要和关联元数据保存在本机缓存，提示词不把这些 Windows 路径交给远端执行。远程续聊暂不支持附带本机参考文件；引用本机文件时会在发送前明确停止，不上传文件内容。远端生成的文件请在 Codex 远程项目中打开。

压缩历史以流式解压读取；普通独立续聊仅在工作台目录内生成完整 JSONL 副本，保留工具记录与上下文压缩信息。桌面同步按原会话 ID 恢复，并核对返回的会话与逻辑路径；原生端自动解压或重新压缩历史后，工作台切换到实际文件继续跟踪。相关回归见 `tests/codex-compressed-history.test.ts`。

退出工作台只断开它的连接，不中断原生端仍在运行的任务。重新打开工作台不会因为读取历史就启动后台；下一次发送或显式打开原生会话时，会按原会话 ID 恢复上下文并核对运行状态。

已有普通会话点击“同步到 Codex”时，如果 Codex 正以普通方式运行，工作台会保存同步请求，显示“等待 Codex 退出后同步”。可以继续在工作台对话，等待期间的新消息也会包含在最终同步中；不会提前改写正在使用的桌面记录。用户方便时退出 Codex，工作台每 5 秒检查一次，等这条会话空闲后自动完成接入并提示完成。此后台流程不打开 Codex 窗口；用户需要查看时，再点击“在 Codex 中打开”。同步请求会保留到下次工作台启动，也可以在“…”菜单取消。已通过工作台联动打开的 Codex 可直接接入其他会话，无需再次退出。它不会自动关闭聊天，也不会在同一份原生记录旁启动第二个后台。已经从可联动入口运行的共享后台可复用。此能力需要安装支持联动入口的 Codex 桌面版；暂仅支持本机网络，管理端出口继续使用普通会话。

新建后台在所有客户端断开、全部已加载会话确认空闲，且至少 15 分钟没有客户端使用后自动退出；未结束的任务或状态不明确时继续保留。连接记录的 24 小时有效期可以续期，不会到点强制关闭任务。工作台不会复制 Codex 登录凭据，也不会修改系统环境变量或桌面安装文件；共享后台通过原生协议更新会话，不再额外抄写桌面索引。后台状态不明确或历史缺失时保留会话与输入，暂停同步请求并显示原因，可从“…”菜单重试；不自动重发任务，也不另建替代会话。

旧版未开启联动的导入会话可能已建立工作台独立副本。可通过 **… → 同步到 Codex** 接入这份副本，保留其后续工作；它不会把有分歧的两份历史自动合并或覆盖。模型与执行权限的更改从下一轮开始生效，当前回复继续运行。

工作流验证：`npm run test:codex-workflow` 使用真实 Codex 后台、本地模拟模型服务和独立本地共享区，验证按需启动、三个会话共用一个后台、并行请求、消息隔离、单会话关闭、原生端续聊、退出工作台后任务继续、重启恢复，以及已有会话接入、原生压缩后的续聊、用户端更多菜单与新建入口。不会调用真实模型服务或消耗个人账号额度。

## 统一启动入口

仓库根目录只保留 `start-user-dev.cmd`（用户版）与 `start-admin-dev.cmd`（管理端）。桌面联动从用户版内部开启，不再提供单独的启动或停止脚本，也不再自动创建演示账号和演示项目。

需要创建普通会话时，关闭新建界面的 **与 Codex 桌面版同步**。已有联动会话仍保留原会话身份。关闭工作台只断开它的连接；共享后台按空闲及有效期策略退出，原生端正在运行时继续保留。

普通入口启动失败时查看 `.test-data/launcher/` 中的日志。联动后台不可达时，工作台保留输入，用户点击 **恢复同步** 后核对原进程并恢复；无法确认身份时停止恢复，不重复发送任务。开发者可运行 `npm run test:codex-workflow -- --extended` 验证异常恢复、生成中接入与审批归属，不会增加用户启动入口。更多处理边界见 [联动问题处理](codex-desktop-followups.md)。

## 连接与数据边界

后台只监听 `127.0.0.1`，原生后台要求独立的随机连接令牌。本机中转入口要求随机路径并拒绝带有浏览器 `Origin` 的请求，供不能附加验证请求头的桌面启动入口使用。中转转发时补充原生后台所需的验证请求头。连接配置保存在当前 Windows 账号权限限制的临时运行目录；不把连接令牌写进命令行或日志，也不复制 Codex 登录凭据。

桌面启动变量只传给该次子进程，不修改系统环境或桌面安装文件。测试窗口使用独立的 `WORKBENCH_DATA_DIR`，本地共享区也独立创建，不覆盖原工作台记录。

## 原先独立后台的桌面联调（未通过）

联调使用桌面版创建的“工作台与 Codex 同步验证”会话，本地共享文件系统代替中央节点。桌面后台版本为 `0.162.0-alpha.17.2`，工作台默认 CLI 为 `0.154.0`；最小真实模型验证使用桌面版相同的 CLI 版本。

1. 桌面版先回复“桌面端初始消息已记录”。
2. 工作台关联该会话并发送最小验证消息，收到 `WORKBENCH_SYNC_OK_20261012`。独立读取接口能读到这条消息，但实际桌面页面没有显示；切换会话后再返回仍没有显示。
3. 用户在桌面版发送“接着聊”，回复仍引用最初的同步记录。检查原始文件，工作台回复和这轮桌面回复都在同一个文件中，但后续桌面记录使用了已经被另一端使用过的序号，读取索引仍只返回前两轮。

因此问题同时涉及页面通知、后台已加载的模型上下文和历史记录序号。它与中央共享节点是否在线无关。仅修改共享文件或 SQLite 索引不能让两个独立后台共享已加载的上下文。

## 原生后台对照验证

2026-10-13 使用本机 `codex-cli 0.162.0-alpha.17.2` 和已登录个人账号进行了独立配置下的真实模型压缩验证，模型为 `gpt-6.1-sol`。通过原生 `thread/compact/start` 手动触发压缩，收到 `contextCompaction` 完成事件。压缩前的 JSONL 文件 20,718 字节在压缩后仍逐字节完整保留，文件追加至 44,497 字节，其中新增 `compacted` 记录及 `replacement_history`。原用户和助手消息的 ID、正文仍由 `thread/read` 返回；重新启动该独立后台并恢复原会话后仍保留原消息。压缩后追问验证词、方案、阈值及下一步，四项均正确。

此次证明本机该版本压缩会更新模型使用的上下文，并保留已存对话记录；不能据此把原聊天替换为压缩内容。文件增大与模型上下文压缩并不矛盾。此次未验证达到完整上下文容量时的自动触发，也未操作真实桌面窗口验证其显示；不能推定 Cursor 的内部存储行为相同。详细记录保存于 `.test-data/codex-compaction-live/run-CZQA1y/result.json`，测试未复制登录文件、执行工具或改动当前桌面会话。

`npm run test:codex-desktop-sync` 使用临时配置和本机 Responses 模拟服务，不登录、不访问中央节点、不消耗模型额度，不修改个人桌面数据库。

- **两个独立后台共用文件和索引**：第二个后台写入的回复可以被读取；回到原后台继续第三轮时，其模型请求仍没有第二个后台的回复。在桌面版同版本的分页历史测试中，第三轮也没有完整出现在读取索引中。这个用例确认共用 SQLite 不能作为产品修复方案；该候选修改已从产品代码撤回。
- **两个客户端连接同一个后台**：两个客户端分别订阅同一会话，依次发送三轮消息。另一端收到新增回复通知，第三轮请求包含第二轮回复，历史完整保留三轮。此用例只验证自建后台的可行性，不代表已经连接到安装的桌面应用。

可通过 `SYNC_DESKTOP_EXE`、`SYNC_CLIENT_EXE` 指定测试版本。结果保存到脚本输出的 `.test-data/native-desktop-sync-时间戳/result.json`，明确区分诊断通过和实际桌面同步通过。

## 后续接入方向

可靠同步应让工作台和桌面版连接同一个 App Server，并订阅同一会话的事件，使用同一个运行中的模型上下文。官方协议提供了会话恢复、事件订阅和多客户端传输能力，参见 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。

本机当前桌面后台使用标准输入输出连接，无法直接通过现有标准输入输出连接再加入一个独立客户端；默认控制 socket 的只读连接探测也没有成功。不能通过另起一个 daemon 来假定它就是桌面版的后台。

### 已找到的桌面启动入口

进一步只读检查本机桌面版 `26.1007.2314.0` 的安装文件后，确认其后台选择逻辑读取 `CODEX_APP_SERVER_WS_URL`，可选择指定的 WebSocket 后台。`CODEX_APP_SERVER_FORCE_CLI=1` 会跳过此路径。代码同时明确禁止 Windows 使用自动连接本地 daemon 的分支，因此不能把该 daemon 分支当作当前 Windows 的解决方法。

这是本机该版本代码中的实现入口，尚未确认属于官方公开、稳定支持的桌面配置。官方 App Server WebSocket 传输仍属于实验能力。本机已经完成消息和上下文的真实验收，但这一结果不意味着入口在其他桌面版本上稳定可用。

可实施的 Beta 接入方式是：由一个本机共享后台统一执行会话，工作台连接它；桌面版从设置了上述启动变量的入口启动，也连接它。两端不再各自运行并写入同一会话。变量只用于该次启动，不全局修改系统环境，也不修改安装文件。

首次联动需要退出以普通方式运行的桌面版，再从工作台点击“在 Codex 中打开”；仅再次启动一个进程可能被桌面单实例机制接管，继续沿用旧后台。代码会检查普通启动与联动启动的区别，不会将未绑定的原生窗口默认为同步成功。本机此前已执行重启并完成真实消息和上下文验证。桌面所需的专属工具和完整插件调用仍需单独验收。

同一会话需轮流发送，等待上一轮完成。此次现有工作流已验证工作台重启后恢复原生 ID 和模型上下文；没有另行验证真实桌面程序自身升级或重启后的全部专属工具行为。

## 已有会话接入

已有会话点击 **… → 同步到 Codex** 后，先检查当前会话已空闲，并核对桌面连接状态。普通方式运行的 Codex 不会被强制关闭，而是保存同步请求、等待退出后接入；当前私有运行器保持可用。程序释放旧的独立运行器，将完整原生记录交给共享后台恢复；不手工修改桌面数据库，也不根据聊天文字拼接替代历史。工具调用、工具结果和原生压缩记录都保留。

接入前失败时原会话和草稿保留，可重试；已切换到共享后台后连接失败时，通过“恢复同步”恢复同一会话，不再退回独立后台写入。已有同标识但内容不同的桌面记录时拒绝覆盖；原始记录缺失时明确提示，不另建文字副本。重复点击不会创建另一条会话。
