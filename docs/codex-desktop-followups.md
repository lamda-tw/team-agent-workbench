# Codex 桌面联动后续问题

2026-10-13 对照远端共享后台实现后登记的四项问题已补齐。以下说明当前处理方式与验证边界；本次修复针对 Codex，Cursor 保持原有边界。

## 共享后台异常退出与连接到期

用户可点击会话工具栏 **…** 中的 **恢复同步**，不需要删除后台记录。程序先核对原管理进程的 PID、启动时间和执行文件。确认原进程已经退出后，通过用户私有目录中的跨进程锁恢复同一连接地址；执行后台仍在时接管它，执行后台也退出时恢复已保存的原会话。连接到期会续期，不再到点强制结束任务。

恢复不会自动发送任务，也不会新建替代会话。管理进程仍存活或无法确认身份、端口被占用、原记录缺失时保留输入并提示重试。原生桌面应用是否自动重连取决于其版本；必要时由用户保存并重新打开原生应用，程序不会强制关闭它。

联动的本机 WebSocket、就绪检查和连接续期始终直连 `127.0.0.1`。即使系统设置了 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NODE_USE_ENV_PROXY=1`，也不会将这些本机连接发往代理；无需修改系统代理。此前缺少本机代理排除时，可能出现“共享后台启动失败”的提示。

## 中途加入正在回复的会话

连接期间暂存会话通知，恢复后读取完整快照，再按原生消息 ID 合并。完成通知提供最终文本，重复通知不会生成重复消息，本地输入回执与资料引用仍保留。补齐期间显示 **正在补齐对话…**；连接关闭后，迟到的快照不会重新写入消息。

## 普通导入会话与桌面数据

已删除自动抄写个人桌面索引的代码与对应旧用例。未开启联动的普通导入会话，在第一次继续对话时复制原记录并调用 `thread/fork` 建立工作台独立会话；后续消息只写私有目录，原桌面会话保持不变。保留导入来源 ID，防止同一原会话重复导入。要双向同步时，在 **… → 同步到 Codex** 接入共享后台，无需 Beta。

已有会话的 **同步到 Codex** 会完整保留原生工具与压缩记录，通过原生恢复协议接入；不手写数据库，不覆盖有分歧的历史。普通模式运行的桌面版会使已有会话转入“等待同步”，原会话仍可继续工作；用户退出 Codex 后，工作台在会话空闲时自动接入最新完整记录并重新打开。连接状态不明时暂停请求并显示原因，不循环强制尝试。已经联动的桌面版可直接接入，无需重启。

## 授权请求的发起端归属

中转按 `turn/start` 的发起连接记录本轮归属。命令、文件、额外权限及结构化提问只交给发起端处理；其他工作台窗口显示 **请到发起任务的窗口确认**。请求统一去重，处理完成或本轮结束后撤销确认卡片；重复点击及迟到的回答不再提交。来源无法确认时，工作台保持只读，不擅自批准或拒绝。

动态工具执行请求仍交给注册工具的原生宿主，不作为人工审批重新分配。已加载共享会话的权限选择随下一次 `turn/start` 提交，不依赖 `thread/resume` 修改已有线程，不打断当前轮次。
