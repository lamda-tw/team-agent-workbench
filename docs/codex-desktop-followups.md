# Codex 桌面联动后续问题

2026-10-13 对照远端共享后台实现后记下的未完成项。已经打开的桌面 Codex / Cursor 不再被直接改写，登记和索引同步改为提醒；下面几项还没有改。

## 共享后台异常退出后不能自己恢复

`CodexDesktopService.active()` 在连接记录还在、但 `readyz` 失败时直接报「无法连接，不会重复发送」。`ensure()` 不会清掉这条记录再启动。进程被硬杀掉时 `bridge.json` 还在，用户要手动删记录才能再联动。`expiresAt` 过了也只报「已失效」，同样不会重建。正常退出会删掉 `bridge.json`，那条路径可以重新启动。

## 中途加入正在回复的会话会丢掉开头

共享连接在 `nativeId` 写上之前，带线程号的通知会被忽略。这段时间会话状态是 `starting`，记录文件监听也不会读。桌面端已经开始的那一轮，工作台要等这轮结束、文件监听恢复后，才能从记录文件补齐。

## 桌面未打开时，索引仍可能静默落后

非联动的原生 Codex 会话，在桌面程序没打开时仍会把私有库的新行抄进个人 `thread_history`。投影已经超前、但对应消息还没落盘时，结果是 `behind`：只隔 200 毫秒重试一次，失败不提醒。这不是共享后台路径；联动会话会直接跳过这次拷贝。

## 授权请求没有按发起端分开

命令和改文件的确认只要属于当前线程就会进工作台，没有看 `sharedTurnOwned`。如果共享后台把审批发给所有订阅者，桌面端发起的确认会同时出现在工作台，两边都能回答。
