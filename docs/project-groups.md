# 项目组与角色

## 选择入口

系统管理员使用**管理端**，以 Linux root/sudo 账号登录；负责创建、停用和重置用户账号，查看全部用户、项目组和共享空间。组内角色不会授予管理端登录资格。

所有项目参与者使用**用户端**，以管理员分配的独立 SSH 账号登录。任意已启用用户都可以自行创建项目组；一个账号可加入多个组，在每个组担任不同角色。

| 操作 | 成员 | 管理者 | 创建者 | 系统管理员（管理端） |
| --- | --- | --- | --- | --- |
| 查看本组资料、上传成果、开展会话 | 可以 | 可以 | 可以 | 全局查看与管理 |
| 创建本组项目、维护说明、整理成员成果、派发和审核任务 | 不可以 | 可以 | 可以 | 全局管理 |
| 添加或移除已有账号、任命管理者 | 不可以 | 不可以 | 可以 | 可以 |
| 移交创建者、删除整个项目组 | 不可以 | 不可以 | 可以 | 可以 |
| 从回收站恢复或彻底清理项目组 | 不可以 | 不可以 | 不可以 | 可以 |
| 创建、停用用户或重置密码 | 不可以 | 不可以 | 不可以 | 可以 |

项目继承所在组的权限。创建者只有一位，管理者可以有多位；创建者同时具备管理者能力。旧版“组管理员”对应这里的“管理者”。

## 用户创建并协作

1. 登录用户端。在**我的工作组**标题旁点击 **＋ → 创建项目组**；尚未加入任何组时，首页也有**创建项目组**按钮。
2. 输入组名。服务器按实际登录身份登记创建者，不能替别人创建或自行声明管理员角色。
3. 首次创建后，填写项目名称、背景、目标、验收标准等资料，建立第一个项目。
4. 点击组名旁的设置按钮，打开**项目组管理**。从已有账号中选择成员，再选择**成员**或**管理者**并添加。新账号由系统管理员先创建。
5. 其他成员刷新工作组，便可进入本组项目。管理者维护项目与内容；成员继续各自的本地会话、整理和提交。

例如 Alice 创建“竞赛优化组”，加入 Bob 为管理者、Carol 为成员。Bob 可以创建“NVFP4 转 HiF4”项目、维护验收指标、整理三人的成果；Carol 可以读取资料和提交实验记录。Bob、Carol 都不能调整组成员或删除组。

## 移交与删除

在**项目组管理 → 移交创建者权限**中选择已有成员，确认后由其接任。原创建者保留管理者权限，最初创建人的历史记录不变。不能直接移出或降级当前创建者，必须先移交。

只有创建者或系统管理员可以删除整个组。确认窗口显示项目数、成员数和占用空间；若成员或内容已变化，需刷新后重新确认。删除后共享内容进入系统回收站，成员无法继续访问，本机代码、会话和已有副本保留。

管理端打开**项目组管理 → 项目组回收站**，可恢复组及内容，或确认彻底清理。彻底清理不能撤销；开始清理后不能恢复，失败时可核对后继续清理。

创建者离职或账号停用时，由系统管理员在全局**项目组管理**中，将创建者移交给已启用账号。普通组管理者不能替代创建者执行这一步。

## 旧组与升级

旧组保留原有成员和内容管理权限，不自动把最早成员提升为创建者。管理端的全局列表将此类组显示为**待指定**；打开组管理，选择接任者并确认移交，即可指定创建者。

正式 Linux 环境先更新两端源码，再由管理端点击**用户管理 → 更新服务端功能**；成员随后重新登录或刷新工作组。旧服务器尚未更新时，用户创建或管理组不可用，已有共享内容保留。若创建中断，管理端的全局列表显示**创建未完成**，可打开后**继续创建项目组**；目录或 Linux 组身份不符时会拒绝接管，需系统管理员核对。

## 验证与边界

服务器根据请求文件所属 Linux UID、账号标记及当前成员关系校验每次操作；客户端隐藏按钮只是交互提示。移出成员时同时调整 Linux 组、目录 ACL 并断开旧连接。权限变动不删除用户本机副本。

本地模式只用于功能与权限逻辑打桩，不能代替 Linux 系统隔离。自动化验证包含：`npm run test:team-groups-ui`（隐藏窗口验证管理端及三种用户角色）、`node scripts/test-background.mjs tests/team-groups.test.ts`、`python -m unittest discover -s tests -p test_team_groups.py`。Windows 上的服务器用例模拟 Linux 账号命令，真实 UID/GID、ACL 与 SSH 连接撤销还需在 Linux 部署环境验收。
