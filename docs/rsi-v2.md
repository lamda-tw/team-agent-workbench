# 项目助手：RSI v2.0

[使用手册](user-guide.md) · [框架原文](../RSI框架.md) · [验证记录](rsi-v2-validation.md)

## 开始使用

1. 使用原有 `start-user-dev.cmd` 启动，选择项目，创建或打开工作会话并明确选择模型。
2. 点击左侧 **项目助手 → 开启项目助手**。默认关闭；开启后会使用个人模型账号的额度。
3. 在 **助手设置** 补充目标、验收标准和分工。项目正式说明仍会作为资料采集。
4. 完成一轮对话后，助手在后台分析。也可以点击 **分析下一步**；用户对话不等待建议或评估完成。
5. 检查建议与依据，点击 **放入会话输入框**，自行编辑和发送。接受建议不意味着已经执行或有效。

分析使用本项目最近创建且未关闭的工作会话模型，页面显示来源会话。任务期间固定提供方、模型、推理强度和网络路线；配置变化后须重新分析或评估。后台使用独立的只读文本任务，不修改原会话上下文，不执行建议中的命令。

**未分项目**也可以使用，对应本机个人空间；其中各个人分组共用同一个助手范围。团队项目按登录账号和项目隔离。管理员仍使用原有 `start-admin-dev.cmd`，无需另起 RSI 服务。

## 建议如何处理

| 操作 | 系统记录与后续行为 |
| --- | --- |
| 查看建议／展开依据 | 展示和进入可见区域分别记录；不推断已阅读 |
| 放入会话输入框 | 记录接受；不自动发送、执行、提交或确认成功 |
| 修改建议 | 保存修改事件，后续采用修改后的文字 |
| 不适用 | 要求原因；只影响当前项目的学习材料 |
| 稍后再看 | 记录延后；不是失败，也不是永久偏好 |
| 关闭建议 | 默认列表隐藏，可勾选显示已关闭建议 |
| 记录实际结果 | 填写结果依据，可选尚未验证、有效、未达标或返工；属于用户确认，不冒充自动测量 |

没有操作不算拒绝。会话中 Agent 声称成功属于推断；工具返回属于观察记录，测试退出码也不自动等于项目成功。项目助手的失败、预算耗尽和建议均不阻止正常对话。

## 策略怎样变好

先登记案例，再学习，最后独立对照。没有足够证据时继续使用当前策略是正常结果。

1. 在 **项目证据** 更新并检查来源。在 **策略与验证 → 保留验收案例** 事先选择证据、应做动作关键词及禁止动作。
2. 至少准备三个不同案例，包含一个不应提出建议的案例。案例冻结来源版本、截止时间和项目配置；学习不会获得其证据与预期答案。
3. 根据明确反馈点击 **从反馈提炼改进**。也可开启反馈后自动提炼；候选不会自行发布。
4. 点击 **运行独立对照**。基线和候选使用相同模型、相同冻结输入，预期关键词不进入模型请求。
5. 通过后才可 **发布此策略**。项目证据、配置或模型变化会使旧评估失效。发现不合适可 **回退上一版本**。

当前判分器按预先约定的动作关键词、建议有无、禁止动作和输出开销检查，质量需提高至少 0.05，不能增加遗漏，不允许打扰案例产生建议。它适合可明确判定的流程验收，不等于开放任务的完整语义评价或因果证明。实际项目收益仍需独立测试和用户确认。

当前候选可调整提示词及检索顺序。冷却时间和建议数量固定继承基线，避免用内容回放证明未经测量的时机改进；底层模型参数、工具权限和预算不由学习改变。策略应表达条件与做法，当前成绩、已完成状态等临时事实不能固化为长期指令。

## 跨项目与长期偏好

**长期建议偏好**仅来自用户明确填写，同一团队身份的本地项目共享；本项目偏好和分工单独保存。不会从一次点击或一个项目推断长期性格、信任或偏好。

同账号可访问项目的已发布策略可 **作为本项目候选** 引入。只复制策略，不复制原项目会话，必须在目标项目重新独立验证。相同策略族在至少两个项目通过并发布后，记录为跨项目经验；仍不自动覆盖其他项目，也不跨账号共享。不同电脑的 RSI 记录当前独立保存。

## 采集、预算与存储

- 采集当前账号可访问项目的开放工作会话、用户明确要求、工具记录、正式项目说明、已有成果与团队内容变化；不收集轨迹上传目录。
- 消息、工具返回与 Agent 推断保留来源、操作者、发生时间、采集时间、版本、内容哈希及关联会话。重复来源修订去重，同一事实的不同来源不重复计算为成功次数。
- 默认每日每项目最多 24 次后台调用；一次对照每案例调用两次。失败调用也计数，不自动无限重试。
- 默认参考上下文 12,000 字符，含裁剪后的项目设置和证据；最多 40 条。固定协议和策略提示另有上限，未把字符数冒称为模型 token 数。
- 自动建议有 10 分钟冷却、最多两条，并按优先级排序、去重；免打扰直接跳过建议。单账号同一时刻只跑一个助手任务，忙碌的工作会话先等待本轮结束。
- 原始记录、反馈、冻结案例、候选、对照输出和版本保存在本机账号数据目录的 `rsi-v2.json`，采用原子写入。不开新的共享目录，不改变 Linux 权限体系。
- 删除会话时清除其证据、建议、受影响的冻结案例和派生策略；正常关闭会话不等于删除。重启标记中断任务，不自动重发模型请求。

## 与框架的对应

| 框架元素 | 实现 |
| --- | --- |
| G／P／E／S | 项目说明、目标验收、角色和明确偏好、环境记录、带未知项的状态判断 |
| O／M | `rsi-workbench.ts` 采集与 `rsi-v2.json` 证据事件账本 |
| K／C／A | 有效策略、按时间和范围过滤的有界检索、结构化建议及引用校验 |
| T／D／U | 异步调度、冷却去重、建议卡片、分开的界面行为与用户结果事件 |
| Y／F／L | 实际执行依据和独立测量、归因假设、候选提示及检索策略 |
| V／R | 冻结案例对照、质量与开销门槛、显式发布与回退 |
| W／M0／B／X | 明确偏好与免打扰、固定模型、调用和上下文预算、账号项目权限 |

没有把整张概念图包装成已验证的通用智能：自动修改外围代码、跨用户经验发布、通用语义评审、隐式信任推断及全量文件监视均不在此版执行范围。

## 开发验证入口

```powershell
npm run typecheck
npm run test:rsi
npm run build
npm run test:rsi-ui
npm run test:rsi-research -- --proxy http://127.0.0.1:7897
```

最后一项真实使用已登录 Codex 账号，固定 `gpt-6-astra` / low。代理可省略，模型可用 `--model` 指定并写入报告。共享服务器和账号权限在隔离目录打桩，模型调用不打桩；输出 `.test-data/rsi-research-<时间戳>/report.json` 与 `report.md`，失败以非零退出码结束，原始试验不覆盖。
