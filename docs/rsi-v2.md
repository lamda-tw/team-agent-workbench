# AI推荐：项目分析与反馈（v2.1）

[使用手册](user-guide.md) · [框架原文](../RSI框架.md)

## 开启与关闭

1. 使用原有 `start-user-dev.cmd` 启动，在“我的工作组”选择项目。
2. 点击项目可展开 **AI推荐** 滑动开关，再次点击可收起；其他项目未选中时不显示。收起不改变开关状态。切换开关立即保存，无需进入设置或再次确认。
3. 点击项目旁的齿轮，在 **AI推荐** 页选择 Agent、模型、思考强度（模型支持时）和网络连接。登录与额度查看沿用新建会话的控件，配置独立保存在本账号、本项目中。选择默认模型时，每项后台任务启动前解析实际模型。
4. 再次点击开关即可关闭；等待中的分析会撤销，正在进行的后台调用会取消，正常会话继续。

开关默认开启，按当前账号和项目分别保存在本机；关闭一个项目不会关闭其他项目，也不会改变其他成员的设置。升级时，未主动配置过的旧项目改用默认开启；用户明确保存的关闭设置和旧的“免打扰”继续保留，重新开启后恢复分析。

点击项目下的 **AI推荐** 文字打开右侧项目工作区。推荐与成员提问共用一个面板，通过顶部标签切换；数字表示待处理推荐或未读提问。新推荐到达时更新数量，不强制弹出、切换页面或阻止继续对话。

多条推荐同时保留：左侧选择条目，右侧默认显示一句当前情况和一段建议；原因、条件、未知及原文依据可展开查看。窄面板中列表位于详情上方。每条推荐独立处理：

- **接受**立即记录选择，可选关联当前账号在本项目中的开放工作会话，并填写推荐反馈；两项都可以留空。
- **拒绝**立即记录选择，推荐反馈可填可不填。
- 处理后可点 **改为拒绝／改为接受**。改判针对整条推荐；原决定和反馈保留在历史里，新决定下的反馈与关联重新填写。其他窗口已经改判时，旧草稿不能自动套到新决定上。
- **保存补充**保存关联和反馈；关联仅记录关系，不向会话发送消息，也不代表已执行或验证成功。
- **关闭**关闭这一条推荐，保留原接受／拒绝状态和已保存补充；未判断时关闭不等于拒绝。可从列表重新打开。
- 面板右上角的 **收起**隐藏整个面板。切换推荐、切换提问或收起再打开，会保留本次面板中的补充草稿；切换账号或项目后以已保存信息为准。

原成员提问的发送、回复、附件和关联会话流程保留。AI推荐不会自动加入输入框、改变会话上下文、执行命令、修改成果或上传共享空间。后台生成建议也不代表用户已经查看或采纳。

**推荐反馈评价的是推荐本身**：例如描述是否具体、背景是否足够、关注点是否有价值、抽象层次是否适合当前项目判断。仍是一个选填文本框，无需逐项评分。例如：“请先说明两个会话分别掌握了什么信息，再解释差异如何影响当前方案选择；只提醒更新记录，关注点偏低。”这类反馈用于改进推荐方式，不作为新的项目任务、验收目标或执行完成记录。新反馈记录评价对象，旧反馈不补写推断标签；后台根据内容区分推荐评价与一次性的业务安排。

接受表示认可当前推荐的主要判断或行动，可以另提表达改进；上例否定推荐的关注点，应选择拒绝。系统不会按文字情绪自动改判。若决定与文字相互矛盾，后台保留原始选择，只采用无歧义的评价，不能将它当成“推荐有效”的证据。每条反馈绑定当时的决定；修改或清空后，旧文字仍可审计，但不作为当前意见反复学习。

推荐使用项目独立配置，关闭前台会话、创建新会话或切换前台模型，都不会改变推荐模型。升级已有项目时，只在尚未配置的情况下迁入原可用会话的模型一次；之后由项目设置控制。后台没有额外的每日调用次数限制，仍消耗个人模型额度。

## 项目材料和增量上下文

- 范围覆盖当前账号在项目内的全部工作会话，包括已关闭会话、用户要求、工具结果、正式项目说明、个人成果和可访问的共享内容变更。不读取其他成员未共享的个人会话，不读取轨迹上传目录。
- 每条材料记录项目、会话 ID 与名称、消息 ID、轮次或日志顺序、内容类型、版本和来源。关联同一原生会话的重复导入只采集一份；用户陈述、工具观察、模型推断分别标注。
- 原始材料留在本机账本。每项推荐使用独立后台逻辑会话，输入为 **项目概况＋本次增量＋相关历史原文＋已有建议及反馈**，不向用户会话注入推荐，也不复用用户对话的执行上下文。
- 默认参考材料上限 **12,000 字符**，可配置 2,000～24,000 字符。协议与策略提示单独限制；字符数不等于 token 数。去掉原来的 20 条会话、30 条消息和工具日志尾部限制，大项目分批分析，不宣称单次调用已阅读所有历史。
- 每个来源分别记录已分析版本及字符位置。长消息分片读取，剩余部分进入后续批次；成功返回空推荐也推进进度，失败不推进。会话记忆按来源版本和原文区间保留多条摘要，新片段不覆盖旧约束；修订或删除使相关条目失效。每轮只选择预算内相关记忆，不保证全部历史同时入模；摘要不能替代原文或把推断升级为事实。

## 提示词与可读性

推荐生成和策略学习的提示词统一维护在 `src/core/rsi-prompts.ts`。判断原则适用于不同项目：围绕目标、现状和变化选择有行动价值的下一步，不将某个算法、开发流程或一次实验结果硬编码成通用规则。

- **给人阅读**：默认只展示一句当前情况和一小段建议。当前情况写清具体对象及其状态或变化；建议写清对什么做什么、为了支持什么判断。不用主题标签代替问题，不堆叠名词，也不凭空填充细节。详细依据、真实前提和影响判断的未知放在展开信息；决定能否执行的关键前提仍在正文说明。
- **给模型处理**：任务约定、可迭代策略、参考材料分别放在 `TASK_CONTRACT`、`POLICY_DATA`、`REFERENCE_DATA`。约定包括输入含义、证据规则、选择原则、字段职责和完整输出结构；原文与反馈不能改变任务约定。实际生成和保留案例评估复用同一提示词入口。
- **给后续分析保留**：项目概况和反馈保留为对象；每条会话记忆按 `constraints`（约束）、`observations`（观察）、`decisions`（决定）、`openQuestions`（未决问题）分栏，并带会话与证据 ID。旧版文字摘要仍可读取；结构化摘要也受 1,200 字符限制，不把计划或用户接受写成已完成。
- **给策略学习**：输入明确区分当前策略、反馈证据和当时的推荐示例。候选只能调整可复用的判断原则及材料选取偏好；当前进度等一次性事实不进入长期策略。冷却时间与建议数量从实际基线继承，不在提示词中写死。

结构、长度、引用及会话归属由程序校验；可读性和事实解释仍需结合实际输出判断，不能仅靠 JSON 校验保证。没有值得推进的新事项时允许无推荐，也不要求对已有充分依据的事项反复查证。

## 触发与执行

1. 打开项目、开启推荐或保存推荐配置时检查待处理变化；已处理且未变化的材料不会重复自动调用模型。
2. 前台一轮完成、原生会话稳定记录刷新、共享资料变化会收集增量，约 **25 秒**合并窗口内的变化。正在执行的一轮只在稳定后进入分析；其他会话继续工作。
3. 普通新进展沿用 **10 分钟**推荐冷却期，冷却到期自动继续，不必等待用户再发消息。大段历史的后续分片按批次继续；正式项目目标和配置变化优先检查。
4. 每个项目同一时刻只运行一项后台任务。推荐与学习分别排队；不同项目可以独立运行，前台不被阻塞。
5. 每次分析冻结模型、策略、材料版本及参考正文。完成时检查引用依据和正式目标：无关的新消息留到下一轮；依据被修改或目标改变时重新分析，不展示过期候选。
6. 网络或模型调用失败保留待处理材料，稍后重试；关闭项目开关取消等待和后台任务。应用退出不保持进程运行，重新进入项目后恢复待处理变化。

## 升级、记忆与策略版本

本机账号数据目录中的 `rsi-v2.json` 文件名保留，数据协议升级到 **3**。首次读取旧协议 2 文件时先保存 `rsi-v2.json.v2-backup`，不覆盖已有备份。数据写入采用原子替换；旧窗口数据迁入账号目录时，一并迁移本账号的 RSI 策略、证据、反馈和分析进度。

应用版本与策略版本分开：代码跟踪运行内核、输入输出协议、初始策略和评估器；运行数据保存每个策略的完整提示模板、规则、协议版本、证据、候选、评估与发布记录。升级不会用新的默认提示覆盖已保存策略。2.1 首次迁移为旧策略补齐显式协议和模板快照，保留已经学到的规则；旧协议下的评估须重新通过后才能发布新候选。后续默认模板变化只作用于新策略，已有模板可精确恢复或回退。

本版新模板标记为 `structured-v2`：固定约定与策略规则分别保存并组装，不通过替换提示词中的文字更新规则。已有模板快照保持原样；从旧模板提炼的新候选采用结构化约定，需要与原基线评估后才能发布。已有结构化模板的候选继续继承其冻结约定。后台运行快照同时记录模板和规则的哈希，便于核对实际输入。

删除会话仍遵守原有删除边界：清除相关证据、推荐、冻结案例和派生策略，避免删除内容继续参与学习。普通版本升级不会执行此清理。

## 策略能力与学习边界

后台保留证据收集、反馈账本、候选提炼、冻结案例对照、显式发布及回退接口。本版界面提供推荐处理与反馈，不提供策略发布或评审页面。

自动学习默认关闭，不自动发布策略。因此普通用户保存反馈后，现行策略不会自动变化。接受、拒绝、关闭分别记录；只接受或不填写原因的拒绝不等于效果证据，不能据此认定建议有效或已形成可学习经验。

提炼输入把每条推荐、对应的接受／拒绝、最新完整反馈和独立结果组成一个反馈包，优先保证反馈完整，再补当时的原文；装不下最新完整反馈时停止，不截断后继续推断。已替代的意见不重复计样，同一输入不重复调用；没有新的可复用规则时记录“保持现行策略”，不制造候选。候选记录完整学习来源，包括通过历史记忆或旧推荐间接使用的材料。反馈改判、清空或来源删除后，相关未发布候选须重新提炼。

独立对照先登记至少三个不同案例，包含一个不应建议的案例，再提炼候选。学习排除保留案例原文、对应推荐上的反馈，以及经记忆间接带入的材料。基线与候选使用相同模型和冻结输入。关键词、遗漏、打扰、禁止动作及输出开销仅构成**基础回归检查**，要求不退化；通过不等于推荐质量提高。

发布还需要对该次对照结果进行**人工质量评审**，核对事实与依据、推荐是否解决当前问题、背景是否充分、表达和关注层次是否改善，并填写理由。评审绑定具体评估、策略、模型和项目版本；重新评估或相关状态变化后失效。后台接口为 `rsi.evaluation.review`，通过后才能调用 `rsi.publish`；界面暂不提供策略评审／发布入口。不会由生成候选的模型自行批准自己的改进。

候选只调整提示词及检索顺序，不改变底层模型或权限；冷却时间与建议数量继承基线。跨项目只允许同账号复制已验证策略为候选，目标项目仍须重新验证；不复制原项目会话。长期偏好仅来自明确填写。

## 基础测试

```powershell
npm run typecheck
npm run test:rsi
npm run build:check
```
