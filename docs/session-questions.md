# Session 成员提问

工作 Session 顶部的“提问”打开侧边窗口。填写问题、可分享的补充资料或链接，多选当前项目所属用户组的其他成员后发送。普通成员也可以提问，不要求管理员身份。

接收人会收到系统通知，并在“动态 → 提问动态”看到卡片。卡片可以关联同项目中自己的工作 Session；点击“关联并回答”后，工作台在该 Session 空闲时开始回答，并把本轮最终答复自动回传。一个 Session 收到多个问题时依次处理；不同成员可以同时回答。同一成员后续点击“关联并补充回答”，会追加一条答复。

发问人看到全部接收人的进度。每人单独一条回复栏，只包含这个人的答复。每位回答者只看到自己的往来。问题及可见答复会作为关联 Session 的“AI 参考内容”，下一轮发送时补充。

回复默认不会进入发问人的 Session。发问人可以手动把某一位的回复引入选定 Session：回复正文在对话里可见，只有标明来源的说明不显示。对方第一次回答后，可以改为和这一位自动对话。自动对话占用一个 Session，只接收这个人的回复，输入框禁用；模型如果还要提问，会自动写好并只发给这个人，多个人则各用一个 Session 并排队处理。模型也可以判断可以结束，这时自动往返停止，提问仍保持开放，直到有人确认。

接收人的 Session 开始回答时，模型会先收到一条用户看不见的说明，标明随后的问题和资料是其他成员发来的。回答者可以随时结束提问，包括问到一半。提问结束会轻量通知已经回复或已经形成对话的人，并刷新提问工作区；这条通知不进入 Session。不传送完整会话或个人日志。补充资料目前支持文字和链接。

## 关闭规则

- 问题始终开放，直到发问人或已参与对话的回答者点击“结束提问”。所有成员都已答复、或自动对话建议结束，都不会自动关闭。
- 结束状态在操作者的本地动态立即更新，其他在线成员在下次同步时更新（当前间隔 5 秒）。离线成员重连后同步。已经回复或已经关联 Session 的人会收到轻量通知。
- 服务端关闭后拒绝新答复，历史答复仍可查看。如果答复先于关闭提交成功，则保留；如果关闭先提交，则不再回传。
- 关闭问题不会停止、关闭或删除任何关联 Session。正在生成的内容留在回答者自己的 Session；是否关闭 Session 由其本人决定。
- 回答者关闭或停止自己的 Session，只终止其本地回答任务，不会关闭别人的问题。

## 可靠性与接入

问题状态通过现有团队存储通道共享。服务端在现有全局文件锁内更新独立问题记录；本地共享模式使用注册表锁。按问题 ID 去重发问，按回答轮次 ID 去重答复，各成员答复只追加。同一成员的运行任务有独立占用标记，避免两个客户端同时代答。

本地队列、待送达答案、已读版本和通知版本保存在账号隔离的 `questions.json`。断线后用同一个答案 ID 自动重送，不重新执行模型。应用重启时，对已开始但未确认完成的模型任务显示中断，需要用户检查后重新回答，避免重复执行。普通进度变化及其他回答者的私有答复不会反复产生未读提醒。

自动回答复用现有工作 Session 的发送和完成流程，因此适用于已经可以发送任务的 Codex、Cursor CLI 和 Claude Code 会话；当前被禁用的 Cursor 桌面共享接入不额外启用。跨成员共享的是问题及答复，各人 CLI 的工作目录和本地会话 ID 仍由各自工作台管理。

需要同时更新客户端和服务端的 `server/content.py`；仅更新客户端不能给旧服务端增加问题协议。实际系统通知还受操作系统通知设置影响。

## 验证

`tests/team-questions.test.ts` 覆盖权限、多人同时回复、去重、关闭与答复竞态、Session 队列、断线回传、重启恢复、账号切换、停止与重新回答、关闭界面，以及 Codex/Cursor 协议替身的完成回传。

`tests/test_content.py` 中的问题用例验证服务端权限、单独可见性、追加答复、关闭与重试规则。测试不启动真实桌面客户端或真实模型 CLI。
