# Codex 历史会话创建子会话的恢复

创建子会话沿用已有原生上下文，不发起新对话、不执行压缩，也不使用阶段摘要替代原生历史。正常创建仍只提交一次 `thread/fork`。

## 已处理的兼容问题

- 尚待注册的迁移记录、中途失败的私有导入，重新连接时会重新定位自身 `.jsonl` / `.jsonl.zst` 文件，并向 `thread/resume` 提供实际路径。记录重新压缩或首次导入失败后，不再丢失恢复路径。已注册的正常会话仍按 ID 恢复，由 Codex 原生索引选择回退或移动后的当前记录，避免目录中旧副本覆盖当前历史。
- 账号工作区迁移同时保留属于该账号会话的压缩记录；不会混拷整个 Codex 数据库或其他账号的记录。已经完成的旧迁移不会自动重新扫描和覆盖目标目录；若当时遗漏记录，需要从保留的旧目录恢复原文件。
- 当 Codex 明确返回 `failed to prepare paginated fork: ... missing projection state ...` 时，工作台调用一次 `thread/turns/list`（只请求最近一轮的元数据），让原生历史读取路径有机会准备索引，再尝试一次分支请求。该恢复依赖当前 Codex 版本能从保留的记录恢复索引；并非对所有分页历史错误都有效。
- 仅在父会话空闲且期间未发生新一轮时允许重试。生成中、等待授权、连接关闭或父会话发生变化，都不自动移动分叉时点。超时、断连和未知错误不会自动重放可能已成功的创建请求。

## 错误定位

错误区分准备原会话记录、恢复父会话、准备历史索引、创建原生分支，并保留完整原始错误。失败阶段及原始错误也写入该会话本地 `events.jsonl`，不会作为对话消息插入模型上下文。

`prepare_fork failed to resolve fork lineage`、来源文件缺失或记录损坏不等同于“缺少索引”，不能通过重试或补写一个索引标记来恢复。需要恢复完整原始记录及其引用来源，再使用原生接口创建分支。当前恢复不擅自拼接历史，不手工伪造 Codex 数据库索引，也不更改原会话的压缩内容。

## 验证范围

后台测试覆盖明确索引错误的有界恢复、未知结果不重试、生成时点保护、恢复失败状态、私有导入重试路径和账号迁移的压缩记录。使用临时目录与协议替身；未在反馈问题的另一台电脑进行现场验证。仅凭不完整的 `failed to prepare ...` 不能确定该电脑的具体原因。
