# Cursor 原生联动（Beta）

## 使用方式

1. 在工作台的 **Beta 功能** 中开启 **Cursor 原生联动**。
2. 从左侧“本地会话”旁的 **接入 Cursor 会话** 选择 **原生会话 · Beta**，点击 **打开 Cursor 并读取会话**。首次建立受管理连接时，若已有普通 Cursor 进程，请保存并退出后再操作；工作台不会强行关闭它。
3. 在普通 IDE 中打开要关联的原生聊天，回到工作台刷新、勾选并导入。同一工作目录只保留一个 IDE 窗口；关联多条聊天时保留各自的原生标签页。
4. 之后可从两端续聊。工作台提交的消息先写入本机队列，当前原生操作完成并保存后才执行下一条。原生窗口仍使用其自己的排队和停止机制。

工作台不启动另一个 Cursor CLI 来续聊，也不将聊天文字复制进另一份模型上下文。模型、Agent / Plan 等模式和运行权限可在工作台输入框下方选择，选项和当前值读取关联的 Cursor 原生会话；修改调用原生控制，由原生端确认后更新显示。在 Cursor 中修改时，工作台也会同步显示。

Skill、MCP、规则、引用资料、授权、提问卡片和手动 `/summarize` 仍在 Cursor 原生窗口中操作，可点击 **在 Cursor 中打开**。工作台不会再维护一套独立配置或附加提示词。自动压缩由同一个原生执行者完成。

普通 CLI 会话仍能独立创建、导入和使用；它们不与原生聊天拼接。独立的 **Cursor Agents Window** 暂不接入此 Beta，同时打开该窗口时会暂停发送，避免再次进入两个后台副本。

## 模型、模式与权限

- 修改设置不创建新会话，也不停止正在生成的回复。工作台的待生效更改在本轮结束后处理；后续排队消息等待设置确认后再发送。
- 在另一端修改设置导致版本变化时，工作台不覆盖它。可以重新选择，或点击 **沿用 Cursor 当前设置** 取消待处理更改。
- 权限名称、禁用项和选择范围来自 Cursor。部分运行权限是 Cursor 应用级设置，可能影响其他会话；管理员策略、会话覆盖及原生确认继续生效。工作台不会替用户点击原生确认窗口。
- 模型参数（例如推理强度、上下文档位）在 Cursor 中调整，工作台显示原生选中标签并在发送前检查设置是否变化。暂不在工作台提供参数编辑。
- 原生设置无法读取、确认尚未完成或选择了多 Agent / 多模型运行时，保留等待项；不猜测权限、不改用 CLI 执行。联动目前只支持同一条原生会话的单一执行者。
- 待生效更改落盘保留，但重启后不会自动重做未经确认的设置操作，需要核对后重新选择或沿用当前设置。

## 等待、停止与恢复

- **等待前一轮结束**：请求已保存在本机，尚未提交给模型，可以取消等待。
- **等待关联会话连接**：原生窗口关闭或正在显示其他会话。点击 **在 Cursor 中打开** 回到这条会话；请求仍保留在原队列中。
- **等待原生设置确认**：模型、模式或权限尚未确认，后续消息等待确认后执行。
- **原生已接收**：已有对应原生消息 ID；该轮只执行一次。历史出现后不再重复展示一个相同的等待卡片。
- **停止当前任务**：先暂停等待队列，再操作关联会话的原生停止按钮。停止后继续观察历史；不会因停止一次任务就失去后续原生消息。
- **等待队列已暂停**：等待项保留，需要明确点击继续。取消等待项、加入新消息或重新打开工作台不会自行恢复暂停的队列。
- **提交结果待确认**：重新确认使用同一个请求 ID；也可取消这次提交。取消记录先落盘，迟到的同 ID 提交不能再次进入执行。
- **送达待核对**：原生发送动作的回执不明确。不会重发；可核对原生消息后确认已送达，或结束此请求。

退出工作台会断开管理连接，保留持久化记录，不发送原生 Stop。重开后使用原会话 ID 恢复；连接不可用时保留历史和等待项，不回退 CLI、不新建替代 Agent。关闭工作台里的这条会话，会取消尚未送达的等待项。

## 多条会话一起使用

每条关联会话保留自己的历史、输入和等待队列。普通 IDE 当前显示哪条聊天，工作台才会向那条聊天发送或修改设置；其他会话的待发消息继续保留，后台刷新不会替用户切换标签页。

需要继续另一条聊天时，在工作台选中它并点击 **在 Cursor 中打开**。工作台根据原生会话 ID 切回已打开的标签页，即使两条聊天同名也不会混用。如果已关闭这条原生标签页，需要先从 Cursor 的聊天历史中重新打开。

完全退出 Cursor 后，也可从上述按钮重新启动。工作台会等待原生标签页恢复，再核对会话身份；排队请求沿用原 ID，已经完成或送达状态不明的请求不会自动重发。若 Cursor 未恢复该标签页，按提示手动打开原会话后重试。

模型按原生会话选取；部分权限设置可能由多个会话共用。如果在另一条会话修改了这类权限，工作台会重新读取实际值，旧的待生效选择不能覆盖新值。

## 历史与上下文

历史来自 Cursor 本地数据库的只读一致性快照，按原生索引顺序展示；包含用户/助手正文、思考、工具调用、成功和失败结果，以及工具引用的大内容文件。模型输入与上下文压缩仍由原生 Cursor 管理，历史展示不被重新喂给模型。

压缩后的原生摘要可能遗漏某些旧事实，这是原生压缩本身的行为。工作台不生成替代摘要，也不为了让模型答对而重新灌入旧历史。完整历史、工具结果是否保留，与模型摘要是否记得某项事实分别验证。

## 当前边界

- 先关联已保存、在普通 IDE 中打开的原生会话；暂不从“新建工作会话”创建原生关联。该入口创建独立 CLI 会话。
- 原生窗口必须保持关联会话可定位。切换会话后可点击“在 Cursor 中打开”切回已有标签页；出现草稿、重复窗口、历史尚未保存或身份不匹配时，会等待或要求核对，不能改投其他聊天。暂不自动查找并打开已关闭的原生标签页。
- 工作台接入模型、模式和运行权限选择；Skill / MCP、模型详细参数、原生提问和授权仍需在原生窗口完成。
- 原生联动会话的成果整理、Subsession 入口禁用；工作台不会把项目资料等额外内容拼接进原生消息。需要补充上下文时，在 Cursor 原生窗口操作。普通 CLI 会话继续提供原有工作台能力。
- 不将 CLI 历史写入原生数据库，也不为匹配界面而重建原生检查点。
