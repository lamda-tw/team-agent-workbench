# Cursor 原生联动（Beta）

## 使用方式

1. 在工作台的 **Beta 功能** 中开启 **Cursor 原生联动**。
2. 从左侧“本地会话”旁的 **接入 Cursor 会话** 选择 **原生会话 · Beta**，点击 **打开 Cursor 并读取会话**。首次建立受管理连接时，若已有普通 Cursor 进程，请保存并退出后再操作；工作台不会强行关闭它。
3. 在普通 IDE 中打开要关联的原生聊天，回到工作台刷新、勾选并导入。请保留这条会话打开，同一工作目录只保留一个 IDE 窗口。
4. 之后可从两端续聊。工作台提交的消息先写入本机队列，当前原生操作完成并保存后才执行下一条。原生窗口仍使用其自己的排队和停止机制。

工作台不启动另一个 Cursor CLI 来续聊，也不将聊天文字复制进另一份模型上下文。模型、模式、权限、Skill、MCP、授权、提问卡片和手动 /summarize 在 Cursor 原生窗口中操作。自动压缩由同一个原生执行者完成。

普通 CLI 会话仍能独立创建、导入和使用；它们不与原生聊天拼接。独立的 **Cursor Agents Window** 暂不接入此 Beta，同时打开该窗口时会暂停发送，避免再次进入两个后台副本。

## 等待、停止与恢复

- **等待前一轮结束**：请求已保存在本机，尚未提交给模型，可以取消等待。
- **原生已接收**：已有对应原生消息 ID；该轮只执行一次。历史出现后不再重复展示一个相同的等待卡片。
- **停止当前任务**：先暂停等待队列，再操作关联会话的原生停止按钮。停止后继续观察历史；不会因停止一次任务就失去后续原生消息。
- **等待队列已暂停**：等待项保留，需要明确点击继续。取消等待项、加入新消息或重新打开工作台不会自行恢复暂停的队列。
- **提交结果待确认**：重新确认使用同一个请求 ID；也可取消这次提交。取消记录先落盘，迟到的同 ID 提交不能再次进入执行。
- **送达待核对**：原生发送动作的回执不明确。不会重发；可核对原生消息后确认已送达，或结束此请求。

退出工作台会断开管理连接，保留持久化记录，不发送原生 Stop。重开后使用原会话 ID 恢复；连接不可用时保留历史和等待项，不回退 CLI、不新建替代 Agent。关闭工作台里的这条会话，会取消尚未送达的等待项。

## 历史与上下文

历史来自 Cursor 本地数据库的只读一致性快照，按原生索引顺序展示；包含用户/助手正文、思考、工具调用、成功和失败结果，以及工具引用的大内容文件。模型输入与上下文压缩仍由原生 Cursor 管理，历史展示不被重新喂给模型。

压缩后的原生摘要可能遗漏某些旧事实，这是原生压缩本身的行为。工作台不生成替代摘要，也不为了让模型答对而重新灌入旧历史。完整历史、工具结果是否保留，与模型摘要是否记得某项事实分别验证。

## 当前边界

- 先关联已保存、在普通 IDE 中打开的原生会话；暂不从“新建工作会话”创建原生关联。该入口创建独立 CLI 会话。
- 原生窗口必须保持关联会话可定位。切换会话、出现草稿、重复窗口、历史尚未保存或身份不匹配时，会等待或要求核对，不能改投其他聊天。
- 工作台暂不代办原生提问、授权和配置菜单；请在原生窗口完成。
- 原生联动会话的成果整理、Subsession 入口禁用；工作台不会把项目资料等额外内容拼接进原生消息。需要补充上下文时，在 Cursor 原生窗口操作。普通 CLI 会话继续提供原有工作台能力。
- 不将 CLI 历史写入原生数据库，也不为匹配界面而重建原生检查点。
