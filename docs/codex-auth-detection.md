# Codex 登录检测与连接故障

工作台区分本机登录凭据和模型服务连通性。“已保存登录”表示 Codex 的原生凭据存储中存在登录，不保证模型接口当前可达。网络或证书失败不会清除登录，也不会自动打开登录网页。

## 检测流程

1. 启动当前配置的 Codex CLI，初始化 App Server，只调用 `getAuthStatus`，使用 `includeToken: false`、`refreshToken: false`。不读取令牌、不创建会话、不发送模型请求。
2. CLI 不支持该接口或响应格式不兼容时，使用 `account/read`，仍不强制刷新令牌。
3. 兼容查询遇到网络、证书或超时错误时，关闭该检测进程，再用有超时限制的 `codex login status` 确认本地登录。成功时保留登录状态，同时单独显示连接故障；明确的登录过期不会被本地缓存覆盖。
4. 取消检测时关闭进程，不启动后续降级检测。相同提供方、程序路径、工作目录和网络方式的同时检测仍共用一个任务。

`account/read` 在部分 Codex 版本中还会进行工作区路由发现。因此它可能报 `workspace routing discovery timed out`，即使 `codex login status` 已确认登录，且桌面端已有连接仍能工作。本地状态接口避免了这项不必要的前置联网要求。

## 执行时的认证

普通隔离会话通过原生接口沿用凭据，只在内存中传递访问令牌。启动时优先复用有效凭据；令牌即将到期或运行时请求刷新时才刷新。刷新后仍已过期的令牌不传入运行时。账号切换检查保留，网络错误不伪装成登录过期。

本机网络继续继承启动进程的网络与证书环境；管理端出口沿用所选会话的代理配置。此次修改不盲目切换系统代理，不关闭证书校验。实际模型请求仍可能因网络不可达而失败，应在连接设置和任务状态中处理，不能靠本地凭据检查认定网络正常。

## 验证

- 后台协议测试覆盖本地检测、旧版兼容、网络降级、明确过期、超时、取消、输出脱敏、有效凭据复用和按需刷新。
- 对目标电脑做只读检测，确认使用现有 Codex 安装能返回本地登录状态；不发送真实模型任务、不重启桌面端。
- 运行中的用户端需要下次启动加载新代码；隔离构建不覆盖正在运行的文件。
