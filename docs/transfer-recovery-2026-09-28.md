# 传输中断恢复：实现与验证

普通文件上传、成果包、附件和轨迹使用同一传输队列。每条上传记录固定账号、项目、目标路径、内容哈希和请求 ID。SFTP 中途断开后，用户在原记录点击重试：客户端先刷新工作组与项目权限、确认本地快照未改变，再查询同一请求 ID 的服务器回执。若请求仍待处理，只等待结果，不覆盖服务器正在读取的暂存文件；若尚未提交请求，则从头传送，服务端按完整文件哈希校验后发布。服务器明确拒绝的请求在用户再次重试时换用新请求 ID；账号或权限未恢复时不会发送。此流程不做字节偏移续传。

普通共享文件下载也记录账号、项目、远端路径、初次读取的哈希和大小。下载写入临时文件，完成校验后才替换用户选择的目标文件；断线或文件变化不会把部分内容标为成功。重试前重新发现项目并核对远端哈希，版本不一致时保留失败记录，要求重新选择文件。应用重启把未完成任务标为可人工重试，不自动发送或下载。

传输记录区分尚未开始、传输中断、等待服务器回执、服务器拒绝和回执/文件校验失败。上传成功必须匹配原账号、目标、哈希与大小；附件还须匹配附件目标，带附件的成果还须匹配附件清单。

自动化验证：`tests/transfer-recovery.test.ts` 覆盖回执丢失与重启后原请求去重、SFTP 回执和待处理请求、部分上传、权限失效、明确拒绝后重新提交、内容变化阻止重试以及下载恢复；`tests/local-space.test.ts` 覆盖本地文件系统权限变更与下载原子替换；`tests/workflow-states.test.ts` 覆盖队列持久化失败。真实 Linux 服务器断网与管理员改密后的操作仍需在部署环境验收。
