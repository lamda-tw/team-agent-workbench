# 本机项目与自动同步

创建项目默认保存在本机，可以直接设置代码目录、创建会话、修改项目说明、保存个人成果，以及迁入已有会话或整个个人分组。上述操作不要求连接中央节点。迁移保留会话 ID、父子关系、历史、摘要、最近五条日志、输入草稿和成果引用；运行中的会话需要先结束。

在项目设置的「中央节点」中选择账号及工作组，即可关联同步。首次关联账号需要登录以获得真实身份和工作组；已缓存的账号与项目可在断线时完成本机迁移，恢复连接后继续同步。关联操作不会自动共享会话全文、工作目录或整个代码库。账号成果仍按原有账号私有资料规则同步。

## 同步与冲突

- 本机修改立即落盘，后台串行保存同步状态。关联后的修改会触发同步，重连后自动继续，并定期检查中央版本。
- 创建使用固定项目 ID。响应丢失或程序重启后仍重试同一 ID，保留首次请求内容与后续本机修改，避免重复创建或丢失编辑。
- 项目说明和账号资料按「上次同步版本／本机版本／中央版本」比较。不同字段的修改自动合并；同一字段有分歧时，仅暂停该对象，其他对象继续同步。
- 项目列表的设置入口显示冲突提示。项目说明冲突在「项目设置 → 项目资料」处理；账号成果冲突在「自动同步」处理，不放进对话记录。
- 后台 AI 只接收有冲突的文字字段及其共同基础，使用现有模型配置，不读取完整会话、不执行工具。提供合并稿、理由和仍需人判断的分歧。
- 仅能由程序验证为换行格式等价的修改可自动采用。事实、日期、数值、删除或归属分歧由用户选择；文字可手动合并，个人成果还可双方保留。
- 采用前再次核对本机版本和中央版本。旧建议不能覆盖新修改。处理前的双方内容保存在本机合并记录中；没有后续修改时，可恢复处理前版本。
- 连接失败和 AI 临时失败自动重试，权限错误保留本机工作并显示原因。工作组权限管理、对外发布等中央操作仍由服务端验证权限。

## 部署与验证

中央节点需同步更新 `server/content.py`，以支持带固定 ID 的幂等项目创建。旧节点不会被视为已同步，客户端保留待同步项目并显示升级提示。服务更新沿用现有管理员端部署流程。

`project-sync.json` 按账号隔离项目缓存、同步基础与待创建请求；`sync-conflicts.json` 保存 AI 建议和按账号归属的合并记录。完整会话继续使用原有本机存储。

验证使用后台测试替身和临时目录，覆盖断线创建、丢失响应、并发编辑、重启、账号隔离、权限变化、迁移、冲突隔离、AI 字段校验和恢复。构建使用 `node scripts/build.mjs --check`，不覆盖运行中的客户端。
